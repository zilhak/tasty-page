# キーバインド

Tasty のキーバインドは、プリセットで変更したり、よく使う動作ごとに好みのキーの組み合わせを指定したりできます。キーバインドの設定は **設定** <!-- en: Settings --> > **キーバインド** <!-- en: Keybindings --> にあります。

## 表記規則

Tasty はキーバインドを **キーの物理的な位置** を基準に保存します。そのため、同じ設定でも 3 つの OS では押すキーが異なります。

| 設定に記載する名前 | Windows · Linux | macOS |
|-------------------|-----------------|-------|
| `ctrl` | Ctrl | Control（⌃） |
| `alt` | Alt | **Command（⌘）** |
| `shift` | Shift | Shift（⇧） |
| `option` | Win（Windows）· Super（Linux） | Option（⌥） |

macOS の ⌘ は Windows · Linux の Alt と同じ位置にあるため、設定値 `alt+t` は Windows では `Alt+T`、macOS では `Cmd+T` を押します。同様に Windows の Win キーと Linux の Super キーは macOS の Option と同じ位置にあるため、`Win+K` · `Super+K` · `⌥+K` を記録すると、すべて `option+k` として保存され、3 つの OS のどれでもその位置のキーで動作します。Windows · Linux の設定画面では、このキーを `Win` · `Super` と表示します。以下の表の 2 列は、この規則に従って記載しています。

`Win+L` · `Win+D` のように Windows が予約している組み合わせや、GNOME · KDE が使う Super の組み合わせ（Super 単独、多くの Super+文字）は、OS が先に受け取るため Tasty には届きません。これらの組み合わせは記録されず、設定ファイルに記載しても動作しません。

設定ファイルでは `ctrl` · `alt` · `option` · `shift` の 4 つの名前だけを使います。`cmd` · `super` · `win` · `meta` のようなキー名は認識されません。

**非ラテン文字のキーボードでも位置で対応します。** ロシア語・ギリシャ語のようにラテン文字以外の配列を使っていても、キーバインドはキーキャップのラテン文字の位置で認識されます — ロシア語配列で `H` の位置（ロシア語では `Р` が入力されるキー）を修飾キーと一緒に押すと、`Ctrl+Shift+H` のショートカットがそのまま動作します。配列を切り替えても、ショートカットを設定し直す必要はありません。Markdown・Web プレビュー画面上でも同じです。

macOS で設定画面の表記を `⌘` `⌥` `⇧` の記号に変えるには、**設定** > **一般** <!-- en: General --> > **表示** <!-- en: Display --> の **Cmd キー表示** <!-- en: Cmd key display --> · **Option キー表示** <!-- en: Option key display --> · **Shift キー表示** <!-- en: Shift key display --> を変更してください。保存される値は変わりません。

## デフォルトのキーバインド（Tasty プリセット）

初回インストール時は **Tasty** プリセットが適用されています。1 つの動作に複数の組み合わせがある場合は、すべて動作します。

| 動作 | Windows · Linux | macOS |

**再読み込み** は、現在表示しているサーフェスに再読み込みを要求します。Markdown はファイル（リモートの場合はリモートの原文）を読み直し、エクスプローラーはフォルダーを読み直し、ターミナルでは何もしません。エクスプローラーの再読み込みキーと同じキーでも、読み直しは 1 回だけです。Windows · Linux の Markdown・HTML 画面でも、`F2` などのファンクションキーを指定した修飾キーなしのショートカットが動作します。Windows · Linux で修飾キーなしの文字キー（例: `R`）を再読み込みに指定すると、Web 画面でも Tasty がそのキーを受け取るため、その文字は入力されません。設定画面のキー入力は修飾キーなしの文字を受け付けないため、このような割り当ては `~/.tasty/config.toml` でのみ設定できます。ショートカットに指定していないキーや文字は、そのままページに入力されます。再読み込みキーをコピー・貼り付けなどの編集キーにも指定している場合、Web ページとその中の入力欄、HTML アドレス欄では編集だけを行い、再読み込みはしません。HTML アドレス欄に入力している間は、アドレス欄へ移動するキーと重なっていても、そのキーが優先されます。再読み込みに `F5` が指定されている間は、ターミナル内のプログラム（mc · htop など）に `F5` は渡されません。ターミナルプログラムで `F5` を使うには、**設定** > **キーバインド** > **サーフェス** <!-- en: Surface --> で再読み込みキーを空にするか、別のキーに変更してください。

`Ctrl+C` は、選択したテキストがあればコピーし、なければ通常どおり実行中のプログラムを中断します。

Markdown・HTML 画面の本文とその中の入力欄、HTML アドレスバーでも、コピー・切り取り・貼り付け・すべて選択のキーは、現在フォーカスがある場所にだけ動作します。入力欄でのすべて選択はその入力欄の文字だけを、本文ではドキュメント全体を選択します。読み取り専用の欄と本文は、切り取り・貼り付けでは変更されません。Windows · Linux の Web 画面では、ショートカットに指定した `Ctrl+C` · `Ctrl+X` · `Ctrl+V` · `Ctrl+A` は Tasty コマンドとして実行されます。ショートカット設定から削除すると、Web 画面のデフォルトの動作に従います。Windows · Linux では、`Ctrl+C` · `Ctrl+X` · `Ctrl+V` · `Ctrl+A` 以外にショートカットに指定した編集キー（`Alt+C` などのデフォルトのキーや自分で追加したキー）も Web 画面で同じ編集を実行します。Linux では、何も選択していないとき、ショートカットに指定した `Ctrl+C` · `Ctrl+X` はページに渡されます。Web ページの元に戻す・やり直すはエクスプローラーとは別に変更でき、Mac でこのキーを削除すると、Web ページの `Cmd+Z` も動作しなくなります。同じキーをプラグインコマンドにも指定している場合、Web ページでは編集が優先されます。単語単位の移動には、Web 画面と入力欄のデフォルトのキーを使います。Linux でページが応答しない間に編集要求が大量にたまると、その画面で編集キーが動作しなくなることがあります。その場合も文字入力はそのまま使え、その画面を閉じて開き直すと編集キーが復帰します。

**リンクをコピー** にはデフォルトのキーがありません。キーを指定すると、ターミナルのリンクにマウスを重ねたままそのキーを押して、リンクのテキストをすぐにコピーできます。コマンドパレットには表示されません。

### コード入力欄

フックハンドラのシーケンスエディターのように、複数行のコードを入力する欄にフォーカスがある場合にのみ動作します。ターミナルや他のショートカットとは重ならないため、同じキーが別の場所に指定されていても構いません。

| 動作 | Windows · Linux | macOS |
|---------|-----------------|-------|
| コード入力欄で適用 <!-- en: Apply in a code field --> | `Ctrl+Enter` · `Alt+Enter` | `Ctrl+Enter` · `Cmd+Enter` |
| コード入力欄でキャンセル <!-- en: Cancel in a code field --> | `Esc` | `Esc` |

### デフォルト値が空の動作

以下は誤操作を防ぐため、または OS のショートカットと重なるため、デフォルトの組み合わせがありません。必要に応じて直接指定してください。

- **終了** <!-- en: Quit --> · **即時終了** <!-- en: Immediate quit --> · **バックグラウンドに最小化** <!-- en: Minimize to background -->（Mac プリセットには `Cmd+Q` · `Cmd+M`、Linux プリセットには `Ctrl+Q` が入っています）
- **次のタブ** · **前のタブ** の自由な組み合わせ（`Ctrl+Tab` が OS と重なるため空にしています — 番号による切り替えの `Ctrl+L` · `Ctrl+H` は動作します）
- **Markdown を開く** · **エクスプローラーを開く** · **Markdown に切り替え** · **エクスプローラーに切り替え**
- エクスプローラーの **プレビューパネル** <!-- en: Preview panel --> のオン・オフ · **プロパティ** <!-- en: Properties -->
- **ワークスペース・タブ・ペインのプリセットを適用**、**すべてのカテゴリを折りたたむ/展開**
- **ウィンドウを最小化** · **ウィンドウを最大化/拡大** · **ウィンドウを閉じる** — macOS のメニューバーの **ウィンドウ** <!-- en: Window --> メニュー項目には、各動作の最初の組み合わせが表示され、その組み合わせで実行されます。動作を空にしておくと、メニュー項目にもショートカットは表示されません。
- サイドバーの **ツール** メニューの項目 — **ポートスキャナーを開く** <!-- en: Open port scanner --> · **リモートツールを開く** <!-- en: Open remote tools --> · **プリセットウィンドウを開く** <!-- en: Open preset window --> · **チュートリアルを開く** <!-- en: Open tutorial --> · **ファイルピッカを開く** <!-- en: Open file picker -->
- Git ビューアを開く（プラグイン）

## プリセット

**設定** > **キーバインド** > **プリセット** <!-- en: Preset --> には 4 種類あります。プリセットは推奨セットにすぎず、OS によって強制されるものではありません — Windows で Mac プリセットを使うこともできます。

| プリセット | 基準 | Tasty プリセットとの違い |
|--------|------|------------------------|
| **Tasty**（デフォルト） | 独自 | 上の表です。コピー・貼り付け・ズームは 3 つの OS の慣例をすべてまとめています |
| **Mac** | iTerm2 · Terminal.app | `Cmd` が中心です。設定 `Cmd+,` · 通知 `Cmd+Shift+I` · DAG 一覧 `Cmd+Shift+G` · サイドバー `Cmd+Shift+B` / `Cmd+B` · 終了 `Cmd+Q` · バックグラウンド `Cmd+M` · ペインを閉じる `Cmd+Shift+W`。複数の組み合わせをまとめた動作は、`Cmd` 側の 1 つだけが残ります — コピー `Cmd+C` · 貼り付け `Cmd+V` · 切り取り `Cmd+X` · すべて選択 `Cmd+A` · 検索 `Cmd+F` · ズーム `Cmd+=` · `Cmd+-` · `Cmd+0` · コマンドパレット `Cmd+Shift+P` · コード入力欄で適用 `Cmd+Enter`、エクスプローラーのゴミ箱 `Cmd+Backspace` · 元に戻す `Cmd+Z` · やり直す `Cmd+Shift+Z` · 隠しファイル `Cmd+Shift+.`。**アクティブな項目を閉じる** と **ワークスペースを閉じる** は空です |
| **Windows** | Windows Terminal | ペインの分割 `Alt+Shift+E` / `Alt+Shift+D`、サーフェスの分割 `Alt+D` / `Alt+E` · 新しいウィンドウ `Ctrl+Shift+N`。複数の組み合わせをまとめた動作は、`Ctrl` 側だけが残り、`Alt` の組み合わせはなくなります — コピー `Ctrl+C` · 貼り付け `Ctrl+V` · 切り取り `Ctrl+X` · すべて選択 `Ctrl+A` · 検索 `Ctrl+F` · ズーム `Ctrl+=` · `Ctrl+-` · `Ctrl+0` · コマンドパレット `Ctrl+Shift+P` · コード入力欄で適用 `Ctrl+Enter`、エクスプローラーのゴミ箱 `Delete` · 元に戻す `Ctrl+Z` · やり直す `Ctrl+Shift+Z` · `Ctrl+Y` · 隠しファイル `Ctrl+Shift+.` |
| **Linux** | GNOME Terminal | Windows プリセットと同じですが、コピー/貼り付け/切り取りは `Ctrl+Shift+C` / `Ctrl+Shift+V` / `Ctrl+Shift+X` · 終了は `Ctrl+Q` です |

適用手順:

1. **設定** > **キーバインド** > **プリセット** 一覧でプリセットの行をクリックしてください。現在使っているプリセットには **使用中** <!-- en: Active --> が表示されています。
2. 詳細画面の **機能** <!-- en: Action --> / **現在** <!-- en: Current --> / プリセットの 3 列の表で、変更される行を確認してください。
3. 右上の **適用** <!-- en: Apply --> を押してください。この時点では、まだファイルには保存されません。
4. ウィンドウ下部の **保存** <!-- en: Save --> を押してください。

プリセットを適用すると、直接変更したキーバインドはすべてプリセットの値に戻ります。

## 別のコンピューターに移す — インポート / エクスポート

**設定** > **キーバインド** の左側の一覧の一番下（区切り線の下）にある **インポート / エクスポート** <!-- en: Import / Export --> で、キーバインドの構成全体を 1 つのファイルで移せます。一般のショートカット・番号による切り替え規則・スクリプトのショートカット・プラグインのショートカットがすべて含まれます。

エクスポート:

1. **エクスポート…** <!-- en: Export… --> を押してください。
2. 保存先のフォルダーを選び、下部の **ファイル名** <!-- en: File name --> 欄で名前を決めてから **保存** を押してください。デフォルトの名前は `tasty-keybindings-<日付>.toml` です。一覧で既存のファイルを押すと、その名前が欄に入り、すでにある名前の場合は警告が表示され、ボタンが **上書き** <!-- en: Overwrite --> に変わります。
3. 保存されると、通知にファイルのパスが表示されます。まだ保存していない編集も含まれます。

エクスポート中は、**エクスポート…** ボタンの名前と幅はそのままで無効になり、ボタンの横に進行状況の表示と **エクスポート中…** の文言が表示されます。同じエクスポートをもう一度押すことはできませんが、他の設定は引き続き編集できます。設定ウィンドウを閉じたり、エクスポートするキーバインドの構成を変更したりすると、以前の処理の成功・失敗の案内は表示されません。すでに受け付けたファイルの書き込みは続行されます。

保存できない場合（例: 読み取り専用のフォルダー）、**エクスポート** 行の中に **エクスポートファイルを書き込めませんでした** <!-- en: The export wasn't written --> が表示されます。**再試行** <!-- en: Try again --> で同じ場所に再度書き込むか、**別の場所を選ぶ…** <!-- en: Choose another location… --> で別の場所を選んでください。この案内が表示されている間は、**エクスポート…** ボタンは押せません。案内の中央の文は、フォルダーが読み取り専用の場合・書き込み権限がない場合・ディスクがいっぱいの場合で、それぞれ異なる内容になります。その 3 つのどれでもない場合は「書き込みが完了しませんでした」と表示し、その下の小さな灰色の行に OS が返した原文を付け加えます（長い場合は省略され、マウスを重ねると全文が表示されます）。

結果を確認できない場合は、**エクスポート結果不明** の案内が表示されます。対象のファイルを確認してから、手動で再試行してください。自動では書き込みを繰り返しません。**再試行** は、現在編集中の構成をエクスポートします。ファイルは同じフォルダーの一時ファイルを介して置き換え、対応している既存のアクセス権限を保持しますが、すべてのファイル属性や電源障害への耐久性を保証するものではありません。

インポート:

1. **インポート…** <!-- en: Import… --> を押して、移してきたファイルを開いてください。すぐには適用されず、比較画面が表示されます。
2. **一般のショートカット** <!-- en: General bindings --> · **クイック切り替え (グループ別)** <!-- en: Quick switch (by group) --> · **スクリプトのショートカット** <!-- en: Script bindings --> · **プラグイン別のショートカット設定** <!-- en: Plugin overrides --> の 4 つのグループで、現在の値とインポートする値が並んで表示されます。最初は変更される行だけが表示され、右上の **全 N 件を表示** <!-- en: Show all N --> ですべて表示できます。
3. インポートしない行は、左側のチェックを外してください。グループのタイトルのチェックは、そのグループ全体をオン・オフします。
4. 右上の **適用** <!-- en: Apply --> を押してください。この時点では、まだファイルには保存されません。
5. ウィンドウ下部の **保存** を押してください。**キャンセル** すると、インポートした内容もすべて破棄されます。

知っておくこと:

- クイック切り替えは、タブ・ワークスペース・カテゴリごとにインポートします。各グループの修飾キーと番号ごとのキーは、まとめて適用されます。
- このコンピューターにだけあるプラグインのショートカットは、ファイルになくても削除されません。逆に、このコンピューターにインストールされていないプラグインのショートカットはインポートされず、そのことが比較画面に 1 行で表示されます。
- ファイルの読み込み中にスキップした部分がある場合（より新しいバージョンの tasty が書き込んだファイル、このバージョンが認識しない動作など）、比較画面の上にある **警告付きで読み込みました** <!-- en: Read with warnings --> ボックスに 1 行ずつまとめて表示されます。4 行以上ある場合は 3 行だけが表示され、残りは **さらに N 件を表示** <!-- en: Show N more --> で展開できます。
- インポートしたショートカットに、Windows の `Win+L` · `Win+D` · `Win+E` · `Win+R` · `Win+I` · `Win+Tab` のように OS が先に使う可能性のある組み合わせがある場合、同じボックスに「Windows が Win+L を先に使う可能性があるため、Tasty に渡されないことがあります。」のような行が追加されます。警告だけで、インポートはそのまま行われます。Linux では、`Super` だけを押すショートカットが該当します。
- キーバインドのファイルではないものを選ぶと、比較画面の代わりに **このファイルはショートカットとして読み込めません** <!-- en: This file can't be read as keybindings --> が表示され、何も変更されません。**別のファイルを選ぶ** <!-- en: Choose another file --> で選び直してください。

### 別の OS で作成したファイルをインポートする場合

キーバインドのファイルは、OS に関係なくそのままインポートできます。Mac で `Option` を使って作成したショートカットは、Windows では `Win`、Linux では `Super` を押すと動作し、逆も同じです。**エクスプローラーのドラッグ切り替えキー** <!-- en: Explorer drag flip modifier -->（**設定** > **キーバインド** > **一般** の一番下）のデフォルト値は Mac が `Option`、Windows · Linux が `Ctrl` のため、Mac でエクスポートしたファイルをインポートすると、Windows · Linux では `Win` · `Super` を押しながらドラッグすることで移動とコピーが切り替わります。

## キーバインドを 1 つ変更する

1. **設定**（`Ctrl+,`）> **キーバインド** を開いてください。左側のサブタブは動作の対象ごとに分かれています — **一般** · **ワークスペース** · **ペイン** <!-- en: Pane --> · **タブ** · **サーフェス** · **クリップボード** · **ズーム** · **エクスプローラー** · **スクリプト実行** <!-- en: Run Scripts --> · **プリセット** · **プラグイン** · **インポート / エクスポート**。
2. 変更する動作のキーボタンをクリックすると、**キーの組み合わせを押してください...** <!-- en: Press key combination... --> に変わります。希望する組み合わせを押してください。
3. 同じ動作に組み合わせをもう 1 つ追加するには、**ショートカットを追加** <!-- en: Add binding --> を押してください。
4. 記録中に `Esc` を押すと、そのスロットが空になります。
5. すでに別の動作が使っている組み合わせの場合、**ショートカットが重複しています** <!-- en: Shortcut already in use --> ポップアップが表示されます。**上書き** <!-- en: Overwrite --> を選ぶと、既存の動作の組み合わせが削除され、この動作に移ります。
6. **保存** を押してください。**キャンセル** <!-- en: Cancel --> すると、すべて破棄されます。

記録の規則:

- 文字・数字・スペースなどの入力キーは、修飾キー（Ctrl/Alt/Shift）を 1 つ以上一緒に押すと登録されます。`W` 単独は無視されます。
- `F1`~`F24` · `Tab` · `Enter` のようなキーは、修飾キーなしでも登録されます。
- 修飾キーを素早く 2 回押すダブルタップ（`Shift` を 2 回など）は、ワークスペース・タブ・サーフェスを開く・閉じる・分割する・移動する、設定・通知を開く、終了するなどの動作にのみ記録されます。ダブルタップで実行されない欄（コマンドパレット、スクリプト、プラグインコマンド、番号による切り替えなど）では、値は変わらず案内文が表示されます。設定ファイルにすでに記載されている、実行されないダブルタップは削除せず、画面下部に警告として表示します。macOS の `alt+alt` は ⌘ を 2 回押すことで、⌥ を 2 回押す操作はダブルタップには使いません。
- `Esc` は「スロットを空にする」操作用に予約されているため、ショートカットとして記録できません。`Esc` がデフォルト値の **全画面ステージを終了** · **コード入力欄でキャンセル** を元に戻すには、プリセットを再適用してください。
- プラグインのショートカット（**プラグイン** サブタブ）が本体のショートカットと重なる場合、**プラグイン側が先に** 動作します。

## プラグインのキーバインドを変更する

**プラグイン** サブタブで、上部の **プラグイン:** <!-- en: Plugin: --> ドロップダウンからプラグインを選ぶと、そのプラグインのコマンドが 1 行ずつ表示されます。

- 方式のドロップダウンで **ホスト継承** <!-- en: Inherit --> を選ぶと、Tasty の動作（例: `clipboard.paste`）の 1 つのキーに従います。行の下に、現在従っているキーが表示されます。
- **独自設定** <!-- en: Custom --> は、他のサブタブと同じ方法でキーを記録します。キーボタンをクリックして組み合わせを押し、`+` でキーを追加できます。記録中の `Esc` はそのキーを削除し、キーをすべて削除すると、そのコマンドにはショートカットがなくなります。記録中にプラグインや方式を変更したり、**リセット** を押したりすると、記録がキャンセルされます。キーが多い場合やウィンドウが狭い場合は、キーボタンと **リセット** が次の行に続き、すべてのキーが表示されます。
- 設定ファイルを直接編集し、どの入力にも一致しないキー（例: `ctrl+shft+h`）が入っている場合、そのキーボタンには記載された文字列がそのままエラーの枠線付きで表示され、行の下に **認識できないキー:** <!-- en: Unrecognized key: --> が付きます。そのキーでは実行されません。
- `cmd+k`·`super+k`·`win+k`·`meta+k` のように OS のキー名を記載した場合は、代わりに「Win·Super·Option は `option`、Cmd は `alt` と記載してください。」という案内が付きます。設定ファイルは、どの OS でも同じ意味になるよう、キーの位置名だけを受け付けます。
- 設定ファイルのキーが Windows の `Win+L` のように OS が先に使う可能性のある組み合わせの場合、行の下に「Windows が Win+L を先に使う可能性があるため、Tasty に渡されないことがあります。」という警告が付きます。保存はそのまま行えます。
- **なし** <!-- en: None --> はショートカットを設定しません。
- 未保存の変更があるコマンドは、名前の後ろに点が表示されます。**リセット** <!-- en: Reset --> は個別設定を削除してプラグインのデフォルト値に戻し、個別設定がない場合は押せません。
- 変更は下部の **保存** で閉じたときにのみ適用され、キャンセルするかウィンドウを閉じると破棄されます。

## 番号による切り替えの規則を変更する

タブ・ワークスペース・カテゴリの「n 番目へ」・「次/前」は、**修飾キー 1 つ + キー 1 つ** の規則でまとめられています。**タブ** サブタブの下部と **ワークスペース** サブタブの下部で変更してください。

- **タブ切り替え修飾キー** <!-- en: Tab switch modifier --> · **ワークスペース切り替え修飾キー** · **カテゴリ切り替え修飾キー** のドロップダウン — デフォルトは `Ctrl` · `Alt` · `Ctrl+Shift` です。変更すると、そのグループの番号ごとのキー（タブ 10・ワークスペース 9・カテゴリ 10）が一括で変わります。
- **1 番目のタブ:** ~ **10 番目のタブ:** などのスロットボタン — 修飾キーなしでキーを 1 つだけ押してください（**キーを1つ押してください (修飾キーなし)...** <!-- en: Press a key (no modifier)... -->）。たとえば 1 番目のスロットを `Q` に変更すると、`Ctrl+Q` が 1 番目のタブになり、修飾キーを押している間にタブに表示される番号も `Q` に変わります。
- **次のタブ:** · **前のタブ:** など — 同じくキー 1 つです。デフォルトは vi 式の `L`/`H`（タブ）、`J`/`K`（ワークスペース・カテゴリ）です。
- ドロップダウンで **個別指定** <!-- en: Custom --> を選ぶと、共通の修飾キーの代わりに、スロットごとに異なる組み合わせ（`Ctrl+Alt+1` など）を記録します。この場合、番号は表示されません。規則方式に戻すと、そのグループはデフォルト値にリセットされます。

<a id="ポップアップにフォーカスがあるとキーバインドが効きません"></a>

## ポップアップで入力中のキーバインド

検索バー・ファイル選択・コマンドパレットのように入力を受け付けるポップアップに **フォーカスがある間は、キーバインドが
動作しません。** 検索語を入力しているときに `Alt+W` のようなキーでサーフェスが閉じるのを防ぐための動作です。ポップアップが表示されているだけでフォーカスがない場合、キーバインドは通常どおり動作します。

ターミナル操作に戻るには、次のいずれかを使ってください。

- **`Esc`** — フォーカスのあるポップアップからフォーカスを外します。外側をクリックすると閉じる種類の場合は、一緒に閉じ、
  それ以外のポップアップは開いたままフォーカスだけが外れます。開いていてもフォーカスのない他のポップアップは、
  そのまま残ります。
- **ポップアップの外側をクリック** — `Esc` と同じ結果になります。

設定ウィンドウや通知パネルが表示されている場合、`Esc` はそちらを先に閉じます。

## キーバインドを覚えずに済む 2 つの方法

- **修飾キーのヒント** — `Ctrl` · `Alt` · `Shift` などを 0.5 秒以上押し続けると（Shift 単独は 1.2 秒）、サイドバーの下に、その組み合わせで始まるショートカットの一覧が表示されます。キーを離すと消えます。Windows · Linux では、`Win` · `Super` はそのキーを使うショートカットが 1 つでもある場合にのみ一覧を表示します。**設定** > **一般** > **アクセシビリティ** <!-- en: Accessibility --> > **修飾キーのヒントを表示** <!-- en: Show modifier key hints --> でオフにでき、パネルはドラッグで移動したりサイズを変更したりできます。
- **コマンドパレット** — `Ctrl+Shift+P` またはステータスバー右側のパレットのショートカットキーキャップです。動作名を入力して `Enter` で実行してください。キーバインドタブの動作と、有効なプラグインのグローバルコマンドが検索されます。ただし、コマンドパレット自体、**全画面ステージを終了**、マウスの下のリンクを対象とする **リンクをコピー**、コード入力欄のキー、エクスプローラーの項目間の移動・選択範囲の拡張・開く・選択解除のキーは表示されません（エクスプローラーの名前の変更・ゴミ箱に移動は表示されます）。スクリプトのショートカットもパレットには表示されません。検索語の欄はフォーカスがなくても背景と枠線で区別でき、入力中はフォーカスの枠線が表示されます。

## 設定ファイルを直接編集する

`~/.tasty/config.toml` の `[keybindings]` セクションに保存されます。値は OS に依存しない名前なので、ファイルを別の OS に移してもそのまま使えます。

```toml
[keybindings]
new_tab = ["alt+t"]
copy = ["ctrl+c", "alt+c", "ctrl+shift+c"]
quit = []                      # 空にするとショートカットなし
 tab_switch_modifier = "ctrl"   # "ctrl+shift" のような組み合わせも可能
tab_switch_slot_keys = ["1", "2", "3", "4", "5", "6", "7", "8", "9", "0"]
tab_switch_next_key = "l"
tab_switch_prev_key = "h"
```

`+` キー自体は `ctrl++` または `ctrl+plus`、`-` は `ctrl+-` または `ctrl+minus`、`=` は `ctrl+=` または `ctrl+equals` と記載します。ファイル編集全般については [設定](settings.md) を参照してください。
