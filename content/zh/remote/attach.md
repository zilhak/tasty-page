# 继续远程工作（attach）

Tasty 的远程附加通过 SSH 在本地显示并操作另一台计算机上运行的 Tasty 工作区。本地显示的远程工作区称为镜像。连接期间，镜像端占用该工作区，远程端可以查看，但无法输入。

## 概念

- 附加会显示**已在运行的远程 Tasty** 的工作区，不会打开新的远程 Shell。远程计算机上必须运行 Tasty（可以是 GUI，也可以是不显示窗口的[无界面构建](../getting-started/install.md#无界面构建)）。
- 远程工作区由显示镜像的一端**独占**。在此期间，远程端用户可以查看终端，但无法输入（只读）。断开连接后恢复。
- 镜像工作区在侧栏中带有天蓝色 **远程** <!-- en: REMOTE --> 标记。通过 **添加远程工作区** <!-- en: Add remote workspace --> 对话框附加的行会保存，重启后回到原位。通过 CLI 附加的镜像不会保存。
- 远程 Tasty 无需位于 PATH 中。只要能读取端口文件（`~/.tasty/tasty.port`）即可。

## 1. 创建配置档

配置档有两种，均保存在 `~/.tasty/remote-profiles.toml` 中。

| 种类 | 内容 | 用途 |
|---|---|---|
| `ssh` | **仅连接信息**，如主机、用户、端口、identity | 用于 `tasty tool ssh` 连接，由附加配置档引用 |
| `tasty-attach` | 附加所需的连接设置（引用 ssh 配置档或直接输入）＋远程 tasty 路径、端口发现方式 | 附加和远程查询**仅使用此种类** |

直接使用 `ssh` 配置档附加会被拒绝。必须创建一个 `tasty-attach` 配置档。

### 通过 GUI

1. 侧边栏的工具按钮 → **工具** <!-- en: Tools --> 菜单 → **远程连接…** <!-- en: Remote connections… -->。
2. **远程配置档** <!-- en: Remote profiles --> 标签页 → **添加配置档** <!-- en: Add profile -->。填写名称、主机、用户、端口、Shell 并保存。将 Shell 保持为 `auto` 时，保存时会通过 SSH 连接一次以检测 Shell。
   - 对于已在 `~/.ssh/config` 中的主机，可在配置档列表下方的**来自 SSH 配置** <!-- en: From ssh config --> 区域，使用主机右侧的**添加配置档** <!-- en: Add profile --> 直接创建。仅保存别名，因此修改 ssh config 后会随之更新。已创建的主机会显示**已在配置档中** <!-- en: in profiles --> 标记，替代按钮。此列表在打开弹窗时读取一次，因此修改 ssh config 后重新打开弹窗即可。
   - 先在 **Passkey** 标签页中注册密钥文件，再从配置档的 Passkey 下拉列表中选择。机密值在 `~/.tasty/passkeys.toml` 中仅以路径引用。
3. **附加**标签页 → **添加附加** <!-- en: Add attach -->。填写名称，在**连接** <!-- en: Connection --> 中选择 **SSH 配置档**（引用上面创建的配置档）或**直接输入（内联）**。
   - **远程 TASTY** <!-- en: Remote tasty --> 组：**可执行文件**（远程 tasty 路径，默认为 `tasty`）、**端口模式**、**端口文件**。如果 tasty 不在远程 PATH 中，在可执行文件中填写完整路径，或将端口模式设为 `file-unix`。

保存期间，保存按钮会暂时禁用。失败后会保留输入值和错误说明，可修改后重新保存。取消或关闭弹窗后，已受理的保存仍会继续，延迟完成的保存不会覆盖重新打开的表单输入。新 Passkey 的名称若与现有条目相同，会被拒绝，不会替换现有凭据。

编辑 Passkey 时，即使修改值后将其清空，延迟加载的值也不会覆盖输入。取消后重新编辑时，仅接收本次编辑请求的值。无法加载凭据时，会在当前编辑界面显示错误。

### 通过 CLI

CLI 的配置档和 Passkey 修改命令会在文件锁内，将更改应用到最新列表。不会覆盖损坏或无法读取的列表。`add-ssh` 的 SSH 检测在保存成功后开始，不会覆盖检测期间被其他命令修改的配置档。

Passkey 的 inline 文件、凭据列表和配置档引用按顺序保存，不会一次性回滚多个文件。若错误中显示前一阶段是否保存成功，请检查对应列表和引用状态。删除时，可能已完成列表移除，但托管文件清理失败。不会删除通过 `path` 注册的用户文件。Windows inline 保存需要通过 PowerShell 设置并验证 ACL，失败时不会写入机密内容。

文件访问权限（ACL）设置失败时，错误消息也会显示原因。


```sh
# ssh 配置档
tasty tool remote-profile add-ssh --name gx10 --host 10.0.0.5 --user me --port 22 --identity ~/.ssh/id_ed25519
tasty tool remote-profile add-ssh --name win --host 10.0.0.9 --shell powershell --label "Windows 构建 PC"   # 指定 Shell 和显示名称
tasty tool remote-profile list-local                      # ~/.ssh/config 别名列表
tasty tool remote-profile import --from devbox --name devbox   # 将别名导入为 ssh 配置档

# tasty-attach 配置档（引用 ssh 配置档）
tasty tool remote-profile add-attach --name gx10-attach --ssh-ref gx10 \
  --remote-tasty /home/me/tasty/target/release/tasty --port-mode auto

# 查看、修改、删除
tasty tool remote-profile list [--kind ssh|tasty-attach]
tasty tool remote-profile show --name gx10-attach
tasty tool remote-profile edit --name gx10-attach --port-mode file-unix
tasty tool remote-profile detect --name gx10-attach       # 实际连接远程端并验证端口
tasty tool remote-profile remove --name gx10-attach
```

端口模式：

| 值 | 行为 |
|---|---|
| `auto`（默认） | 按 `subcommand` → `file-unix` → `file-windows` 的顺序尝试 |
| `subcommand` | 在远程端运行 `<可执行文件> port` 以获取端口 |
| `file-unix` | 读取远程端的 `~/.tasty/tasty.port`（不运行 tasty） |
| `file-windows` | 读取 Windows 远程端的端口文件 |

指定 `--port-file <路径>` 后，优先读取该文件。

要直接查看远程计算机上当前运行实例的 IPC 端口，在该计算机上运行 `tasty port`。端口模式 `subcommand` 在远程端调用的就是此命令。

## 2. 检查远程连接

```sh
tasty remote check --profile gx10-attach       # alive: gx10 (port 41234, version …, N workspaces)
tasty remote workspaces --profile gx10-attach  # 远程工作区列表（id、名称、是否被占用）
```

`remote check` 找到端口并实际收到响应后，才会判定为 alive。如果程序已退出，仅留下端口文件，则显示为 `dead`。失败原因分为四种：SSH 连接失败／远程实例未运行／响应解析失败／超时。

连接尝试不会无限等待。上限为 SSH 连接 10 秒、每个阶段 20 秒、总计 45 秒。线路较慢时，可通过 ssh 配置档的 `--option ConnectTimeout=30` 等选项自行延长。

## 3. 通过 GUI 附加

1. 在侧边栏中**右键单击新建工作区（+）按钮**，或右键单击空白背景 → **添加远程工作区** <!-- en: Add remote workspace -->。（启用分类后，分类标题的右键菜单中也有此项。）
2. 在左侧的**附加配置档** <!-- en: Attach profiles --> 中选择配置档。右侧会显示远程工作区列表（若在 20 秒内未收到响应，则停止并显示**重试**）。
3. 选择工作区并点击**连接** <!-- en: Connect -->。其他人已附加的工作区会显示为**使用中** <!-- en: in use -->，无法选择。
   - 选择列表第一行的**新建工作区** <!-- en: New workspace -->，会在远程端以默认名称创建工作区，然后附加（**创建并连接** <!-- en: Create & connect -->）。以此方式创建的工作区会保留在远程端。
   - 列表显示后，可用 `↑` / `↓` 切换行，按 `Enter` 连接。
4. 侧边栏中会出现带有**远程**标记的镜像工作区，并将焦点移至该工作区。连接或镜像准备失败时，会在该窗口中显示包含原因的失败短暂提示。若窗口已关闭，则不显示。

本身是其他 Tasty 镜像的远程工作区会带有 `mirror` 标记并禁用，无法附加。`tasty remote workspaces` 也会在该行下方输出说明。

## 4. 通过 CLI 附加

```sh
tasty tool attach --list                                   # tasty-attach 配置档列表
tasty tool attach gx10-attach --workspace 3                # 镜像整个工作区（在终端中运行）
tasty tool attach gx10-attach 57                           # 仅一个 Surface
tasty tool attach gx10-attach 57 --raw                     # 将本地终端直连远程 Surface（退出 Ctrl+\）
tasty remote attach --profile gx10-attach --workspace 3    # 与 tool attach 功能相同的长形式
tasty remote attach --ssh me@10.0.0.5 --workspace 3        # 不使用配置档的一次性连接
tasty remote new-workspace --profile gx10-attach --name build --cwd /home/me/proj   # 在远程端创建工作区
```

### 附加到正在运行的 Tasty 窗口

正在运行的 Tasty 会自行打开 SSH 隧道，将远程工作区作为镜像附加到此窗口。不会移动焦点。要附加现有工作区，用 `--workspace` 指定远程 ID。`--profile` 接受 `tasty-attach` 配置档名称；若不使用配置档连接，则改用 `--ssh <目标>`。

```sh
tasty remote attach --into-gui --workspace 3 --profile gx10-attach
tasty remote attach --into-gui --workspace 3 --ssh me@10.0.0.5
```

连接现有工作区的命令会以一行 JSON 输出受理响应，最多等待 90 秒获取连接结果，再以第二行 JSON 输出结果。连接失败或未在 90 秒内收到结果时，以退出码 1 结束。不要仅凭受理响应判断连接成功。

要在远程端新建工作区并立即作为镜像附加，使用 `--new-workspace` 替代 `--workspace`。`--name` 和 `--cwd` 为可选项，`--cwd` 是远程计算机上的路径。此形式以一行 JSON 输出创建结果，不会像连接现有工作区时那样等待第二行结果，因此请通过 `tasty list workspaces` 检查镜像是否已出现。镜像行带有 `[mirror]` 标记。

```sh
tasty remote attach --into-gui --new-workspace --profile gx10-attach --name build --cwd /srv/project
tasty list workspaces
```

`tasty remote new-workspace` 用于创建远程工作区。若还需将其作为镜像附加到本地 GUI，使用 `tasty remote attach --into-gui --new-workspace`。`remote new-workspace` 帮助文本末尾也有此说明。

仍可使用现有的 `--target-port` 形式，通过已打开的 SSH 隧道的本地端口附加。此时需自行准备隧道。

```sh
tasty remote attach --into-gui --target-port 5555 --workspace 3
```

如果同一配置档和远程工作区已对应已保存的远程行，会连接该行而不是创建新镜像。此命令无法重新连接手动断开的行，改用 `tasty remote connect --workspace <本地 id>`。

持有会话令牌的智能体也可使用 `tasty remote attach --into-gui`、`tasty remote connect`、`tasty remote disconnect` 和 `tasty remote refusals`，无需额外权限。但用于检查镜像的 `tasty list workspaces` 需要 `surface.read` 权限。

常用选项：

| 选项 | 适用命令 | 行为 |
|---|---|---|
| `--send <输入>` | `tool attach`, `remote attach` | 附加后立即发送一次输入（解析 `\n` `\r` `\t` `\xNN` 转义） |
| `--send-to <Surface>` | `tool attach`, `remote attach` | 工作区附加中接收 `--send` 的远程 Surface ID |
| `--dump-after <ms>` | `tool attach`, `remote attach` | 在指定时间内收集输出，输出镜像画面后结束（用于无 GUI 检查） |
| `--remote-tasty <路径>` | `remote attach·check·workspaces·new-workspace` | 不使用配置档时的远程 tasty 可执行文件路径（默认为 `tasty`）。指定 `--profile` 后使用配置档的值 |
| `--remote-port-mode <模式>` | 同上 | 端口查找方式（`auto`、`subcommand`、`file-unix`、`file-windows`） |
| `--json` | `remote workspaces`, `remote new-workspace` | 以 JSON 输出结果 |

- 工作区附加会镜像其中的终端，保留拆分结构。
- 图像 Surface 等由插件直接绘制的 Surface 也会显示原有内容，点击和按键输入会传到远程端。自行安装的插件的 Surface 也一样。
- 可在文件浏览器中修改远程计算机上的文件（从 0.12.2 起）。新建文件夹、新建文件、重命名、移到回收站，以及同一连接内的复制、剪切、粘贴和拖放，由远程 Tasty 执行；进度显示、名称冲突弹窗和结果卡片与本地文件浏览器相同。远程 Tasty 也必须为 0.12.2 或更高版本。有以下限制。
  - 远程操作不会保留在撤销历史记录中。要还原，使用结果卡片上的**撤销** <!-- en: Undo -->。
  - 拒绝本地与远程之间、不同远程端之间的粘贴和拖放。
  - 远程 Tasty 为旧版本时，修改文件的菜单项和工具栏按钮会变灰并禁用，工具提示（通过快捷键调用时为通知）会提示更新该计算机上的 Tasty。
  - 远程文件浏览器中无法使用**在系统中打开** <!-- en: Open in system -->、在文件管理器中显示、**添加到收藏夹** <!-- en: Add to Favorites -->、**在新标签页中打开** <!-- en: Open in New Tab -->。
  - 在远程端新建文件夹、新建文件或重命名时，输入的名称会以灰色保留在原处，旁边显示旋转指示器，直到远程端响应。在此期间无法修改或取消。成功后会选中新建条目或关闭重命名弹窗；失败后可继续修改原先输入的名称。
  - 操作期间连接断开时，远程端会在当前条目处停止操作。本地文件浏览器会保留一张说明结果未知的警告卡片，直到手动关闭；重新连接后会重新读取文件夹。卡片上没有重试或撤销按钮。
- 在文件浏览器中双击 Markdown 文件，会在远程计算机上打开该文件的 Markdown 标签页，并显示在此窗口中，不会读取本机同一路径下的文件。若该格式的默认处理器无法用于远程端，则仅列出可用于远程端的处理器；若该格式没有此类处理器，则仅显示说明。
- Markdown Surface 使用本机主题显示远程文档内容，点击地址栏左侧的**重新加载** <!-- en: Reload --> 按钮可重新获取最新内容。远程文档发生更改时，不会自动替换内容，而是用强调色填充重新加载按钮（若远程 Tasty 为无界面构建，颜色不会变化，请自行点击检查）。连接断开并等待重新连接期间，会显示连接已断开的说明，替代原有内容；地址栏和按钮全部禁用，按钮显示**已与远程断开连接** <!-- en: Disconnected from the remote -->。重新连接后会自动获取最新内容。无法打开远程文档中的相对路径图像和文件链接。
- 在远程 Markdown 地址栏中输入远程计算机上的路径，按 `Enter` 或**转到** <!-- en: Go -->，即可将同一 Surface 切换到该远程文件。本机的最近文件列表不会出现在自动补全中。按 `Esc` 会将输入恢复为当前文档的远程路径。无法打开时，会保留输入的路径，并在地址栏下方显示原因。远程端不存在该文件时，显示**无法在远程端打开 …：文件不存在。** <!-- en: Can't open … on the remote: file not found. -->；若远程端因其他原因拒绝，则原样附上远程端发送的英文原因。远程响应前连接断开时，显示**远程响应前连接已断开。重新连接后重试。** <!-- en: Connection lost before the remote answered. Reconnect and try again. -->。此时无法确定远程端是否已发生更改，请重新连接后检查。经过 30 秒仍未收到响应时，地址栏下方显示**仍在等待远程响应…** <!-- en: Still waiting for the remote… -->；即使远程端延迟响应，也会应用其结果。重新输入或按 `Esc` 会清除这些行，此后延迟到达的失败结果不会让它们再次出现。即使延迟打开，文档仍会切换到该文件。
- 远程 Markdown 地址栏左侧的文件夹按钮（**打开远程文件…** <!-- en: Open a remote file… -->）会在远程文档所在的远程文件夹中打开文件选择器。选中的远程文件会在同一 Surface 中打开；若远程端无法打开，则通过短暂提示告知。
- 查看镜像期间，通过**打开 Markdown 文件** <!-- en: Open Markdown File --> 弹窗将 Surface 转换为 Markdown 或打开新标签页时，在弹窗中输入或通过**浏览…** <!-- en: Browse… --> 选择的路径，会作为远程计算机上的文件打开。相对路径以远程终端的当前文件夹为基准。以此方式打开的文件不会保留在本机的最近文件列表中。
- 在 Linux、Windows 和 macOS 上，可查看远程 HTML 文件的正文。接收大文件前，选择**允许**或**拒绝**。脚本遵循本机的 HTML 设置；允许后，会使用已接收的正文重新显示。地址为只读，点击**重新加载**可获取最新正文。连接断开后，已接收的正文会保留，重新加载被禁用。连接旧版本时可能仍显示为空白区域。若对端也支持，还会接收同一文件夹下的 CSS、图像等独立文件。多个大文件会逐个询问；达到总接收量 2MB 的限制时，选择**继续**或**停止**。大文件询问和累计接收量询问不会因等待过久而消失。若等待期间远程传输已过期，点击**允许**或**继续**时会重新请求该文件；若文件大小在此期间发生变化，会再次询问。继续也会接收剩余文件，重新加载也会重新请求失败的文件。已拒绝或接收失败的文件数量会保留到重新加载时。跳转到下级 HTML 时，作为新文档检查。页面取消文件请求时，也会解除接收等待，但保留接收同一文件的其他请求。在 Linux X11（包括设有 `DISPLAY` 且能连接 X 服务器的 Wayland 会话中的 XWayland）、Windows 和 macOS 27 及更高版本上，若两端版本均支持，也可打开 HTTP、HTTPS 网址。请求在远程计算机上执行，因此网页的表单提交或按钮可能改变远程服务的状态。但在 Windows 和 macOS 上，已允许脚本的页面，其 WebRTC 连接可能直接从本机发出。Tasty 会移除页面的 WebRTC 功能以减少此情况，但不保证阻断所有路径。同一站点的请求默认允许，其他站点遵循本机的 HTML 远程内容设置。浏览器安全策略仍然生效。每个响应的传输大小达到 100000 字节、整个文档达到 2000000 字节时，会按现有机制询问是否同意接收。允许脚本会使用已接收的正文重新显示，不会重新提交表单。显式重新加载会重新发送原始请求，并保留同一文档的 Cookie。连接断开时会停止脚本；重新连接或远程地址发生变化时，不会迁移 Cookie 和脚本许可。此时，若专用浏览器存储的准备工作短暂重叠，会在限定时间内等待；达到存储上限或安全检查失败时，会显示错误。在 macOS 上，远程计算机的 `localhost`、`127.0.0.1` 等地址会以 `localhost.tasty.localhost` 等独立名称打开。界面显示原始地址，但页面脚本读取的地址是此名称；文档中通过完整地址指向远程 `localhost` 的图像和请求无法打开。相对路径和链接跳转仍可使用。因未设置 `DISPLAY` 或无法连接 X 服务器而使用 Linux 原生 Wayland 运行时，以及在 macOS 11–26 上，不支持显示远程网址，也不会改由本机连接。在 Linux 上无法查看远程 HTML 文件或网址时，参见[原生 Wayland 故障排除](../help/troubleshooting.md#linux-native-wayland)和 [GTK 初始化及托盘故障排除](../help/troubleshooting.md#linux-gdk-backend)。macOS 最低支持版本仍为 11。
- `--raw` 仅支持 Surface 级别。
- 在终端中运行附加时，未指定 `--no-reconnect` 时，SSH 断开后会自动尝试重新连接。
- 线路较慢而丢失远程端发送的部分画面时，远程端会告知此情况，附加会自行重新附加并获取画面。此时终端会输出一行说明。输出画面后结束的附加，每次运行最多重新附加三次；若仍有丢失，会在输出结果后提示画面可能缺失部分内容。`--raw` 会不限次数地重新附加，并从头重绘画面。不会重新发送通过 `--send` 发送的输入。

从 CLI 直接附加到正在运行的 Tasty 窗口时，使用上面的 `--into-gui`。需要在重启后保留的连接请参阅下方的已保存远程行。

## 5. 连接已保存的远程行

通过 **添加远程工作区** <!-- en: Add remote workspace --> 对话框附加的工作区会保存连接信息以及行的名称、分类和位置。重启后会回到原位，在屏幕上显示时立即尝试连接，包括重启后恢复的活动行、切换窗口焦点和选择行。手动断开的行和在其他位置关闭的行除外。通过 CLI 附加的镜像不会保存，断开后会被清理。

已保存的行连接中断后，会在 **重新连接尝试时长** <!-- en: Keep reconnecting for --> 内尝试重新连接，超时后以断开状态保留在列表中。默认值为 300 秒，范围为 0~3600 秒。设为 0 时不自动重新连接，立即进入断开状态。重新连接的开始、成功和超时通过连接弹窗及卡片和状态标记显示，不显示短暂提示。如果其他客户端已占用工作区、远程工作区不存在或目标本身是镜像，会立即停止重新连接并显示原因。首次连接失败的行会保留原因，在返回该行或请求连接前不会自动重试。

手动断开的行会在弹窗中显示 **连接已断开** <!-- en: Disconnected --> 和“已手动断开此工作区。重新连接前将保持断开。”。切换到其他行再返回不会连接。在弹窗或行菜单中选择连接或重新连接，或在**添加远程工作区** <!-- en: Add remote workspace --> 对话框中选择同一行。智能体通过以下命令显式连接：

```sh
tasty list workspaces
tasty remote connect --workspace 7
```

`--workspace` 为必填参数，接收已保存远程行的 **本地 ID**。示例中的 `7` 是从 `tasty list workspaces` 找到的行 ID，并非远程 ID。连接不会移动焦点。命令先输出一行 JSON 受理响应，再将最终结果输出为第二行 JSON。已连接的行立即成功，正在连接的行会加入当前尝试。结果失败或 90 秒内未返回时，以退出码 1 结束。普通本地工作区、未保存的 CLI 镜像、不存在的 ID、远程工作区已不存在或该行的窗口已关闭时，会立即失败。

向未连接的已保存行发送 `tasty claude spawn --workspace` 等指定工作区的请求时，会开始连接并等待最多 35 秒。重启后尚未连接的行没有窗格、标签页或 Surface，因此只有接受工作区参数的请求可以指定该行。`tasty send`、`tasty read screen` 等指定 Surface 的命令，仅适用于本次运行中连接过且仍有 Surface 的行。连接成功后执行请求，无法连接或被拒绝时返回说明原因的错误。但手动断开的行会返回连接已断开的错误，不执行请求。按照错误提示，先用 `tasty remote connect --workspace <id>` 或行的连接菜单连接。向同一远程目标发送 `tasty remote attach --into-gui` 也不会解除手动断开状态。

仅用 `tasty list workspaces`、`tasty remote workspaces` 或 `tasty remote refusals` 查询列表不会连接行。`tasty list workspaces` 的普通输出带有 `[mirror]` 标记，但不显示连接状态；已保存行的连接状态可在 GUI 弹窗和卡片中查看。

远程工作区在其他位置关闭后，行仍会保留，但再次选择也不会连接，重新连接按钮也会禁用。重启 Tasty 后，该行恢复为未连接状态，可以再次请求连接。

## 镜像中可执行的操作

- 按键输入和鼠标操作会直接传到远程终端。远程端会按本地窗格大小重新布局。
- 若远程端未响应新尺寸，Tasty 会再次请求。若仍无响应（约 10 秒），工作区顶部会显示**无法与远程同步终端大小**横幅，并显示对应标签页的名称。如果多个标签页同名，如拆分后的标签页，则只显示一次名称，并附上数量，如 `Shell ×2`。可通过**重试**（多个时为**全部重试**）再次请求；× 仅关闭横幅。若远程端稍后接受该尺寸，横幅会自动消失。远程 Tasty 为不具备此功能的旧版本时，不会显示横幅。
- 拆分、新建标签页、关闭或重新排序标签页、转换 Surface、恢复已关闭项，均**在远程端执行**，结果会反映到镜像中。创建远程端不具备的 Surface 种类时，会通过短暂提示告知失败。智能体请求的拆分、新建标签页、关闭、移动、转换（包括 Markdown 文档跳转和打开图像），以及未指定打开位置的文件打开请求，若在远程端失败，只记录日志，不显示短暂提示。
- Surface 右键菜单中的**移动 Surface**，仅在同一镜像工作区内于远程端执行。禁止在镜像与其他工作区之间移动。
- 镜像中无法使用标签页右键菜单中的**移动标签页**、**移动窗格**。若移动项或目标位置为镜像，仅显示操作被阻止的短暂提示，不会进行任何更改。
- 在镜像中使用**恢复已关闭项**（默认 `Ctrl+Shift+T`），会恢复远程端已关闭的标签页。该标签页是远程终端，因此输入也会传到远程端。恢复标签页的历史回滚缓冲区，仅在远程窗口中完整显示（镜像从可见画面开始接收）。
  - 智能体通过 CLI 在镜像中关闭的标签页无法恢复，即使在远程窗口中执行恢复也一样。恢复仅针对手动关闭的项目。
  - 恢复仅针对**在该远程工作区中关闭的项目**。若远程端没有可恢复的项目，只会显示说明性短暂提示，不会执行任何操作。本地关闭的标签页不会因此出现在镜像中。返回本地工作区后按同一快捷键，才会恢复本地项目。
- 远程端因 Shell 结束（`exit`）而关闭的标签页，也会立即从镜像中消失。
- 远程终端的完成、需要输入标记（边框、徽标）也会原样显示在镜像中。
- 丢失远程端发送的部分画面时，会显示“远程画面部分丢失” <!-- en: Part of the remote screen was lost --> 短暂提示，镜像会自行重新附加并获取画面（未使用配置档附加的镜像也一样）。重新附加后，回滚缓冲区中可能再次出现相同画面。若在上传剪贴板图像期间发生此情况，上传会以失败结束，可重新尝试。由于远程端可能已保存，不会自动重新发送。
- 粘贴剪贴板图像时，会上传到远程端并输入**远程路径**。除以下情况外，文本按原样输入。
  - 在本地终端截图时，会将本地文件路径和图像放入本地剪贴板。远程端无法读取该本地路径。在镜像终端中使用粘贴快捷键时，若文本是本机截图文件夹 `~/.tasty/screenshots/` 直属文件的路径，且能读取剪贴板图像，则上传图像并输入远程路径。若无法读取图像，例如截图时因无法添加图像而只复制了路径，则原样输入本地路径。
- 在镜像中使用[将截图复制到剪贴板](../using/terminal.md#将截图复制到剪贴板)（`Ctrl+Alt+S`），会在本机截取画面，将文件保存到远程端，再将远程路径和图像一起放入**远程剪贴板**。本地剪贴板不会改变。若远程 Tasty 为不支持复制图像的旧版本，则仅放入路径，并通过短暂提示说明。若因远程连接不存在而无法发送，会提示文件仅保存到本机；若在远程端响应前连接断开，会提示复制尚未确认。
  - 粘贴快捷键读取本地剪贴板。不过，截图后若未在本机复制其他内容，在同一镜像的终端中使用粘贴快捷键，会输入远程端 `~/.tasty/screenshots/` 下的文件路径，代替本地内容。若已复制其他内容，则照常输入该本地内容。
  - 同一路径可以多次粘贴。在该镜像中新截图后，会使用新截图代替之前的截图；该镜像工作区从窗口中消失后，便无法再以此方式粘贴。
  - 远程端返回保存路径前，或响应中没有路径时，输入本地内容。只要文件已保存且返回了路径，即使写入远程剪贴板失败，仍会输入远程路径。
  - 若重新复制的内容与截图前完全相同，会视为未改变，仍输入远程路径。若截图前一刻无法读取本地剪贴板，则该截图无法以此方式粘贴。若远程桌面（RDP）客户端等程序将远程剪贴板复制到本地剪贴板，粘贴快捷键会输入这样复制到本地的内容。
- 将镜像工作区编号传给 `--workspace`，`tasty claude spawn`、`tasty codex spawn` 的子智能体会在远程计算机上运行，并在本地作为该镜像内的子智能体管理。用法见 [Claude · Codex](../agents/claude-codex.md#在已附加的远程工作区中创建子智能体)。
  - 连接断开期间，该子智能体的状态显示为 `unknown`。重新连接到同一个远程 Tasty 后，其间已完成的事件会传递一次。
  - 远程 Tasty 重启后，不会传递重启前创建的子智能体的完成事件。远程 Tasty 为旧版本时，不会创建子智能体，并会报告错误。
- 也会拒绝重新启动镜像 Surface 的 Shell（`tasty surface respawn-terminal`、`tasty terminal respawn`），或将后台 PTY 作为标签页附加到镜像中（`tasty pty attach-surface`）。因为这会将本地 Shell 混入远程终端所在位置。请直接在远程实例上执行。
- 向镜像工作区应用标签页、窗格预设（预设弹窗、`tasty preset apply`）也会因同样原因被拒绝。工作区预设会新建工作区，因此仍可使用。

## 关闭镜像和断开连接

右键点击已保存的远程行可执行以下操作：

- **断开连接** <!-- en: Disconnect -->——结束连接以及正在进行的连接或重新连接尝试，保留行。远程工作区和程序继续运行，远程端可重新输入。再次使用前需要显式连接。
- **在本地关闭** <!-- en: Close locally -->——从此 Tasty 删除行并取消正在进行的连接尝试，保留远程工作区和程序。关闭工作区的快捷键对已保存的行也执行在本地关闭。
- **关闭远程工作区…** <!-- en: Close remote workspace… -->——在已连接状态下打开确认对话框，然后结束远程工作区及所有程序。此操作无法撤销，成功后也会删除已保存的行。手动关闭已连接的已保存行中的最后一个标签页、窗格或 Surface 时，也会要求确认关闭远程工作区。智能体的关闭请求无需确认即可执行。

通过 CLI 附加的未保存镜像在卡片菜单中有 **断开工作区连接** <!-- en: Disconnect Workspace --> 和 **关闭工作区** <!-- en: Close Workspace -->。前者清理本地镜像并保留远程工作，后者结束远程工作区和程序。关闭最后一个标签页、窗格或 Surface 也会关闭远程工作区。关闭远程最后一个工作区后，远程窗口会创建新的终端工作区。

关闭远程工作区时，仅在远程端确认已关闭后才删除本地镜像，并显示“**已关闭远程 Tasty 上的工作区。** <!-- en: Closed the workspace on the remote Tasty. -->”。远程端拒绝时，镜像会保留并显示失败提示。手动请求远程关闭的工作区，无论通过已保存的行还是未保存的镜像附加，都可以从远程窗口的已关闭项目记录中恢复，但原先运行的程序不会恢复。

断开未保存镜像的连接后，如果它是最后一个工作区，本地窗口不会关闭，而会打开新的终端工作区。断开已保存远程行的连接会保留该行。

连接中或重新连接中无法发送远程关闭请求。如果远程 Tasty 不支持此操作，更新远程 Tasty 或仅断开连接。如果在收到响应前连接中断，会提示关闭结果未知。远程工作可能仍在运行，重新连接后确认。

CLI 也可以保留远程工作，仅断开连接：

```sh
tasty remote disconnect --workspace 7
```

`--workspace` 接收 `tasty list workspaces` 中 `[mirror]` 行的 **本地 ID**。已保存的行会留在列表中，用 `tasty remote connect --workspace <本地 id>` 重新连接。未保存的镜像用 `tasty remote attach --into-gui --workspace <远程 id>` 再次附加。已保存的行即使尚未连接，断开命令也会成功并取消正在进行的尝试。

这与远程窗口中的 **强制分离** 不同。强制分离用于从远程计算机移除其他人的连接。

## 释放占用（在远程端）

本地 Tasty 的工作区被其他位置附加并变为只读时，Surface 上会显示**强制分离** <!-- en: Force detach --> 提示。该提示仅在查看该工作区时显示，因此也可直接从侧边栏分离。右键单击被占用的工作区卡片 > **强制分离** <!-- en: Force detach -->，屏幕中央会显示确认弹窗，确认后立即释放占用，无需切换到该工作区。

没有断开他人连接的 CLI 命令。为避免服务器上的智能体误断开正在远程工作的用户，仅允许通过界面分离。在不显示窗口的 Tasty 等无 GUI 服务器上，远程端结束传入的 SSH 会话后，连接会关闭并释放占用。若远程端自动重新连接，可能再次附加。

远程端用户已附加期间，在本地对该工作区执行拆分、新建标签页、`spawn`，通过 CLI 应用标签页或窗格预设（`tasty preset apply`），或将后台 PTY 作为标签页附加（`tasty pty attach-surface`），均会被拒绝并报告“占用中”错误。请使用其他工作区，或强制分离后继续。

## 从远程接收的文件的保存位置

通过附加通道传输的文件保存在 `~/.tasty/transfers/` 中，文件夹上限为 500 MiB。可在**设置** > **常规** > **远程传输** <!-- en: Remote transfer --> 中修改，也可通过 CLI 修改。

```sh
tasty settings get-remote-transfer
tasty settings set-remote-transfer --dir ~/Downloads/tasty --max-mb 2000
```

将 CLI 附加的 `--raw` 输出传给其他命令时，若该命令先退出，附加也会正常结束。
输出设备权限问题等其他写入错误会报告为失败。

## 无响应时断开连接的超时时间

远程附加连接在设定时间内未收到对端任何内容时，会断开连接。默认等待时间已从原先的固定时长延长至 30 秒。可在**设置** <!-- en: Settings --> › **常规** <!-- en: General --> › **远程附加** <!-- en: Remote attach --> 中，修改**附加连接** <!-- en: Attach connections --> 下的**断开前等待时长** <!-- en: Disconnect after -->。单位为秒，范围为 10～600 秒。

保存设置后，无需重启，会从新连接开始应用，已打开的连接保持原样。两端 Tasty 各自使用自己的值，因此即使延长一端的时间，对端仍可能先断开。不读取配置文件的 CLI 附加使用 30 秒。配置文件中的键和超出范围值的处理方式，参见[设置](../customize/settings.md)。

**设置** <!-- en: Settings --> › **常规** <!-- en: General --> › **远程附加** <!-- en: Remote attach --> 中的 **重新连接尝试时长** <!-- en: Keep reconnecting for --> 控制已保存远程行的连接中断后自动重新连接的持续时间。默认 300 秒，范围 0~3600 秒，0 禁用自动重新连接。不适用于手动断开的连接。配置键为 `[remote_attach] reconnect_timeout_secs`。

## 等待响应期间

在镜像中新建标签页或拆分时，会从下一帧开始先显示其位置。服务器确认前，无法向新区域发送输入，但可选择现有标签页或区域继续工作。若等待期间选择了其他位置，延迟完成的操作不会将选择切回。失败请求只会移除其自身的临时区域。

等待响应超过 200ms 时，标签页和侧边栏中会显示旋转指示器，工作区右上角会显示**等待响应** <!-- en: Waiting for response --> 和已用时间。多个请求时，显示数量和最长等待时间。将指针悬停其上，可逐行查看每种请求的最长等待时间。关闭、移动、恢复、转换，以及文件夹、文档、Git 查询，也会在等待响应期间显示，不会阻塞界面或输入。原生 WebView 不会隐藏，而是使用标签页和侧边栏指示。

旋转指示器仅替代标签页图标、侧边栏状态点和折叠侧边栏中的头像，标签页标题和工作区名称不变。将指针悬停在等待中的标签页或工作区上，名称下方会同时显示**正在附加…** <!-- en: Attaching… -->。

普通输入的等待指示，会由支持此功能的服务器确认先前输入是否已到达应用处理边界。这不代表 Shell 命令或程序已结束。不会因无输出的正常输入或长时间运行的命令而持续显示，也不会等待旧服务器不支持的输入确认。连接中断后，已保存的行通过连接弹窗和标记显示状态，未保存的 CLI 镜像则会被清理。

## 故障排除

| 症状 | 检查项 |
|---|---|
| `kind='ssh'` 被拒绝 | 向 `--profile` 传入了 ssh 配置档。创建并指定 `tasty-attach` 配置档 |
| 未找到远程 tasty | 远程端是否正在运行 Tasty。通过 `tasty tool remote-profile detect --name <n>` 验证端口。不在 PATH 中时，指定可执行文件路径或使用 `--port-mode file-unix` |
| 超时 | 检查是否能连接主机及防火墙设置。ssh 配置档 `--option ConnectTimeout=<秒>` |
| SSH 连接失败 | 身份验证、主机密钥。先通过 `tasty tool ssh <ssh 配置档>` 检查能否连接 |
| 提示或报错称目标为此 Tasty 自身 | 配置档的主机（包括主机名、LAN IP）和端口文件，或通过 `--into-gui --target-port` 指定的端口（包括自行打开的 SSH 隧道），指向当前使用的 Tasty。无法附加到自身。要附加到同一计算机上的另一个 Tasty，指定该实例的端口文件 |
| 报错称此构建不支持 `--into-gui` | 接收命令的本地 Tasty 是不显示窗口的[无界面构建](../getting-started/install.md#无界面构建)。没有可显示镜像的窗口，因此不接受请求。请发送给正在通过 GUI 运行的 Tasty |
| 强制结束 Tasty 后仍有 `ssh` 进程残留 | macOS 仅在正常退出（通过菜单退出、关闭窗口）时清理远程附加隧道。强制退出或异常退出后，需手动结束残留的 `ssh -N -L` 进程。Linux、Windows 上会随 Tasty 一起结束 |
| 工作区附加被拒绝 | 其中一个终端已被其他客户端占用。在远程端强制分离 |
| 首次附加时画面短暂闪烁 | 远程端按本地窗格大小重新布局时的正常行为 |
