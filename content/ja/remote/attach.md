# リモートの作業を続ける（attach）

Tasty のリモートアタッチは、SSH を使って別のコンピューターで実行中の Tasty のワークスペースを手元の画面に表示し、操作する機能です。手元の画面に表示されるリモートワークスペースをミラーと呼びます。接続中はミラー側がその作業領域を占有し、リモート側では表示できますが入力はできません。

## 概念

- アタッチは、**すでに実行中のリモート Tasty** のワークスペースを取り込んで表示するものです。新しいリモートシェルを開くものではありません。リモートコンピューターで Tasty が実行されている必要があります（GUI でも、ウィンドウなしで実行される [ヘッドレスビルド](../getting-started/install.md#ヘッドレスビルド) でも構いません）。
- リモートワークスペースは、ミラーとして取り込んだ側が**独占**します。その間、リモート側のユーザーはそのターミナルを表示できますが入力はできません（読み取り専用）。接続を切ると元に戻ります。
- ミラーワークスペースには、サイドバーに水色の **リモート** <!-- en: REMOTE --> の印が付きます。**リモートワークスペースを追加** <!-- en: Add remote workspace --> ダイアログからアタッチした行は保存され、再起動後も同じ場所に戻ります。CLI でアタッチしたミラーは保存されません。
- リモートの Tasty は PATH に含まれていなくても構いません。ポートファイル（`~/.tasty/tasty.port`）さえ読み取れれば十分です。

## 1. プロファイルを作成する

プロファイルは 2 種類あります。どちらも `~/.tasty/remote-profiles.toml` に保存されます。

| 種類 | 含むもの | 用途 |
|---|---|---|
| `ssh` | ホスト・ユーザー・ポート・identity などの**接続情報のみ** | `tasty tool ssh` 接続、アタッチプロファイルから参照 |
| `tasty-attach` | アタッチに使う接続設定（ssh プロファイルの参照または直接入力）+ リモートの tasty のパス・ポート検出方式 | アタッチ・リモート照会には**この種類だけ**を使います |

`ssh` プロファイルで直接アタッチしようとすると拒否されます。必ず `tasty-attach` プロファイルを 1 つ作成してください。

### GUI から

1. サイドバーのツールボタン → **ツール** <!-- en: Tools --> メニュー → **リモート接続…** <!-- en: Remote connections… -->。
2. **リモートプロファイル** <!-- en: Remote profiles --> タブ → **プロファイルを追加** <!-- en: Add profile -->。名前・ホスト・ユーザー・ポート・シェルを入力して保存してください。シェルを `auto` にすると、保存時に SSH で一度接続してシェルを検出します。
   - `~/.ssh/config` にすでにあるホストは、プロファイル一覧の下にある **SSH 設定に登録されたホスト** <!-- en: From ssh config --> セクションで、ホストの右側の **プロファイルを追加** <!-- en: Add profile --> から直接作成してください。別名だけが保存されるため、ssh config を変更してもそのまま追従します。作成済みのホストには、ボタンの代わりに **登録済み** <!-- en: in profiles --> 表示が付きます。この一覧はポップアップを開くときに一度読み込むため、ssh config を変更した後はポップアップを開き直してください。
   - キーファイルは先に **Passkey** タブに登録し、プロファイルの Passkey ドロップダウンで選んでください。secret の値は `~/.tasty/passkeys.toml` 内でパスとしてのみ参照されます。
3. **アタッチ** タブ → **Attach を追加** <!-- en: Add attach -->。名前を入力し、**接続** <!-- en: Connection --> で **SSH プロファイル**（上で作成したものを参照）または **直接入力（インライン）** を選んでください。
   - **リモート TASTY** <!-- en: Remote tasty --> グループ: **実行ファイル**（リモートの tasty のパス、既定値は `tasty`）・**ポートモード**・**ポートファイル**。リモートの PATH に tasty がない場合は、実行ファイルにフルパスを入力するか、ポートモードを `file-unix` にしてください。

保存中は保存ボタンが一時的に無効になります。失敗した場合は入力値とエラー案内が残るため、修正して再び保存できます。キャンセルしたりポップアップを閉じたりしても、受け付け済みの保存は続行され、遅れて完了しても開き直したフォームの入力を上書きしません。新しい Passkey の名前が既存の項目と同じ場合は、既存の認証情報を変更せずに拒否します。

Passkey の編集中に値を変更してから空にしても、遅れて読み込まれた値が入力を上書きすることはありません。キャンセル後に再び編集すると、新しい編集で要求した値だけを受け取ります。認証情報を読み込めない場合は、現在の編集画面にエラーを表示します。

### CLI から

CLI のプロファイル・Passkey 変更コマンドは、ファイルロック内で最新の一覧に変更を適用します。破損した一覧や読み取れない一覧は上書きしません。`add-ssh` の SSH 検出は保存に成功してから開始し、検出中に別のコマンドが変更したプロファイルは上書きしません。

Passkey の inline ファイル、認証情報一覧、プロファイル参照は順に保存し、複数のファイルをまとめて元に戻すことはしません。エラーに前の段階の保存が成功したかどうかが表示された場合は、その一覧と参照の状態を確認してください。削除時には、一覧からの削除が完了しても管理対象ファイルの整理に失敗することがあります。`path` で登録したユーザーファイルは削除しません。Windows の inline 保存には PowerShell の ACL 設定・検証が必要で、失敗した場合は secret の内容を書き込みません。

ファイルのアクセス権限（ACL）の設定に失敗した場合は、エラーメッセージに原因も表示します。


```sh
# ssh プロファイル
tasty tool remote-profile add-ssh --name gx10 --host 10.0.0.5 --user me --port 22 --identity ~/.ssh/id_ed25519
tasty tool remote-profile add-ssh --name win --host 10.0.0.9 --shell powershell --label "Windows ビルド PC"   # シェル・表示名を指定
tasty tool remote-profile list-local                      # ~/.ssh/config の別名一覧
tasty tool remote-profile import --from devbox --name devbox   # 別名を ssh プロファイルに

# tasty-attach プロファイル（ssh プロファイルを参照）
tasty tool remote-profile add-attach --name gx10-attach --ssh-ref gx10 \
  --remote-tasty /home/me/tasty/target/release/tasty --port-mode auto

# 確認・変更・削除
tasty tool remote-profile list [--kind ssh|tasty-attach]
tasty tool remote-profile show --name gx10-attach
tasty tool remote-profile edit --name gx10-attach --port-mode file-unix
tasty tool remote-profile detect --name gx10-attach       # リモートに実際に接続してポートを検証
tasty tool remote-profile remove --name gx10-attach
```

ポートモード:

| 値 | 動作 |
|---|---|
| `auto`（既定） | `subcommand` → `file-unix` → `file-windows` の順に試行します |
| `subcommand` | リモートで `<実行ファイル> port` を実行してポートを取得します |
| `file-unix` | リモートの `~/.tasty/tasty.port` を読み取ります（tasty は実行しません） |
| `file-windows` | Windows リモートのポートファイルを読み取ります |

`--port-file <パス>` を指定すると、そのファイルを最優先で読み取ります。

リモートコンピューターで現在実行中のインスタンスの IPC ポートを直接確認するには、そのコンピューターで `tasty port` を実行してください — ポートモード `subcommand` がリモートで呼び出すのはこのコマンドです。

## 2. リモート接続の確認

```sh
tasty remote check --profile gx10-attach       # alive: gx10 (port 41234, version …, N workspaces)
tasty remote workspaces --profile gx10-attach  # リモートワークスペース一覧（id・名前・占有の有無）
```

`remote check` はポートを見つけた後、実際に応答を受け取って初めて alive と判定します。プログラムが終了し、ポートファイルだけが残っている場合は `dead` と表示されます。失敗の原因は、SSH 接続失敗 / リモートインスタンス未起動 / 応答の解析失敗 / タイムアウトの 4 種類に分けて通知します。

接続の試行で無期限に待つことはありません — SSH 接続は 10 秒、各段階は 20 秒、全体では 45 秒が上限です。回線が遅い場合は、ssh プロファイルの `--option ConnectTimeout=30` のように手動で延長してください。

## 3. GUI からアタッチする

1. サイドバーで **新しいワークスペース**（+）ボタンを右クリックするか、空の背景を右クリック → **リモートワークスペースを追加** <!-- en: Add remote workspace -->。（カテゴリーを有効にしている場合は、カテゴリーヘッダーの右クリックにもあります。）
2. 左側の **アタッチプロファイル** <!-- en: Attach profiles --> でプロファイルを選んでください。右側にリモートワークスペース一覧が表示されます（20 秒以内に応答がない場合は中断し、**再試行** を表示します）。
3. ワークスペースを選んで **接続** <!-- en: Connect -->。すでに別の人がアタッチしているものは **使用中** <!-- en: in use --> と表示され、選べません。
   - 一覧の先頭行の **新しいワークスペース** <!-- en: New workspace --> を選ぶと、リモートに既定の名前でワークスペースを作成してからアタッチします（**作成して接続** <!-- en: Create & connect -->）。この方法で作成したワークスペースはリモートに残ります。
   - 一覧が表示されたら、`↑` / `↓` で行を移動し、`Enter` で接続できます。
4. サイドバーに **リモート** 表示が付いたミラーワークスペースが作成され、そこにフォーカスが移ります。接続やミラーの準備に失敗した場合は、そのウィンドウに理由付きの失敗トーストが表示されます。ウィンドウを閉じていた場合は表示しません。

別の Tasty のミラーであるリモートワークスペースは、`mirror` の印付きで無効になり、アタッチできません。`tasty remote workspaces` もその行の下に案内を出力します。

## 4. CLI からアタッチする

```sh
tasty tool attach --list                                   # tasty-attach プロファイル一覧
tasty tool attach gx10-attach --workspace 3                # ワークスペース全体をミラー化（ターミナルで実行）
tasty tool attach gx10-attach 57                           # サーフェス 1 つだけ
tasty tool attach gx10-attach 57 --raw                     # 手元のターミナルをリモートサーフェスに直結（終了 Ctrl+\）
tasty remote attach --profile gx10-attach --workspace 3    # tool attach と同じ処理の長い形式
tasty remote attach --ssh me@10.0.0.5 --workspace 3        # プロファイルなしで一度だけ
tasty remote new-workspace --profile gx10-attach --name build --cwd /home/me/proj   # リモートにワークスペースを作成
```

### 実行中の Tasty ウィンドウにアタッチする

実行中の Tasty が SSH トンネルを直接開き、リモートワークスペースをこのウィンドウにミラーとしてアタッチします。フォーカスは移しません。既存のワークスペースをアタッチするには、リモート ID を `--workspace` で指定してください。`--profile` には `tasty-attach` プロファイル名を指定し、プロファイルなしで接続するには、代わりに `--ssh <接続先>` を使ってください。

```sh
tasty remote attach --into-gui --workspace 3 --profile gx10-attach
tasty remote attach --into-gui --workspace 3 --ssh me@10.0.0.5
```

既存のワークスペースに接続するコマンドは、受付応答を JSON 1 行で出力し、接続結果を最大 90 秒待ってから、結果を 2 行目の JSON で出力します。接続に失敗するか、90 秒以内に結果を受け取れなかった場合は、終了コード 1 で終了します。受付応答だけで接続に成功したと判断しないでください。

リモートにワークスペースを新規作成し、すぐにミラーとしてアタッチするには、`--workspace` の代わりに `--new-workspace` を使ってください。`--name` と `--cwd` は任意で、`--cwd` はリモートコンピューターのパスです。この形式は作成結果を JSON 1 行で出力します。既存のワークスペースへの接続のように 2 行目の結果を待つ形式ではないため、ミラーが作成されたかは `tasty list workspaces` で確認してください。ミラーの行には `[mirror]` が付きます。

```sh
tasty remote attach --into-gui --new-workspace --profile gx10-attach --name build --cwd /srv/project
tasty list workspaces
```

`tasty remote new-workspace` は、リモートワークスペースを作成するコマンドです。ローカル GUI にミラーとしてアタッチするところまで行うには、`tasty remote attach --into-gui --new-workspace` を使ってください。`remote new-workspace` のヘルプ末尾にもこの案内が表示されます。

すでに開いてある SSH トンネルのローカルポートにアタッチする、従来の `--target-port` 形式もそのまま使えます。この場合、トンネルは手動で用意してください。

```sh
tasty remote attach --into-gui --target-port 5555 --workspace 3
```

同じプロファイルとリモートワークスペースが保存された行にある場合、新しいミラーを作らずにその行に接続します。手動で切断した行にはこのコマンドで再接続できないため、`tasty remote connect --workspace <ローカル id>` を使ってください。

セッショントークンを持つエージェントも、追加の権限なしで `tasty remote attach --into-gui`、`tasty remote connect`、`tasty remote disconnect`、`tasty remote refusals` を使えます。ただし、ミラーの確認に使う `tasty list workspaces` には `surface.read` 権限が必要です。

よく使うオプション:

| オプション | 使用箇所 | 動作 |
|---|---|---|
| `--send <入力>` | `tool attach`, `remote attach` | アタッチ直後に入力を一度送信します（`\n` `\r` `\t` `\xNN` エスケープを解釈します） |
| `--send-to <サーフェス>` | `tool attach`, `remote attach` | ワークスペースのアタッチで `--send` を受け取るリモートサーフェス ID |
| `--dump-after <ms>` | `tool attach`, `remote attach` | 指定時間だけ出力を集め、ミラー画面を出力して終了します（GUI なしで確認する場合） |
| `--remote-tasty <パス>` | `remote attach·check·workspaces·new-workspace` | プロファイルなしで使う場合のリモートの tasty 実行ファイルのパス（既定値は `tasty`）。`--profile` を指定するとプロファイルの値を使います |
| `--remote-port-mode <モード>` | 同上 | ポート検出方式（`auto`・`subcommand`・`file-unix`・`file-windows`） |
| `--json` | `remote workspaces`, `remote new-workspace` | 結果を JSON で出力します |

- ワークスペースのアタッチは、その中のターミナルを分割構造ごとそのままミラー化します。
- 画像サーフェスなど、プラグインが直接描画するサーフェスも内容がそのまま表示され、クリック・キー入力がリモートに送られます。自分でインストールしたプラグインのサーフェスも同様です。
- エクスプローラーでは、リモートコンピューターのファイルを変更できます（0.12.2 以降）。新しいフォルダー・新しいファイル・名前の変更・ゴミ箱への移動、同じ接続内でのコピー・切り取り・貼り付けとドラッグ＆ドロップはリモートの Tasty が実行し、進捗表示・名前の競合ポップアップ・結果カードはローカルのエクスプローラーと同じです。リモートの Tasty も 0.12.2 以降である必要があります。次の制約があります。
  - リモート操作は元に戻す履歴に残りません。元に戻すには、結果カードの **元に戻す** <!-- en: Undo --> を使ってください。
  - ローカルとリモートの間、異なるリモート間での貼り付けとドラッグ＆ドロップは拒否されます。
  - リモートの Tasty が古いバージョンの場合、ファイルを変更するメニュー項目とツールバーボタンはグレー表示で無効になり、ツールチップ（ショートカットで呼び出した場合は通知）でそのコンピューターの Tasty を更新するよう案内します。
  - **システムで開く** <!-- en: Open in system -->・ファイルマネージャーで表示・**お気に入りに追加** <!-- en: Add to Favorites -->・**新しいタブで開く** <!-- en: Open in New Tab --> は、リモートのエクスプローラーでは使えません。
  - リモートに新しいフォルダー・新しいファイルを作成したり名前を変更したりすると、リモートから応答が来るまで、入力した名前がその場所に灰色で残り、隣にスピナーが表示されます。その間は編集もキャンセルもできません。成功すると作成した項目が選択されるか、名前変更ポップアップが閉じ、失敗すると入力した名前をそのまま再編集できます。
  - 操作中に接続が切れると、リモートは処理していた項目で操作を止めます。こちらのエクスプローラーには、結果が不明であることを示す警告カードが閉じるまで残り、再接続するとフォルダーを読み直します。カードには再試行・元に戻すボタンはありません。
- エクスプローラーで Markdown ファイルをダブルクリックすると、リモートコンピューターにそのファイルの Markdown タブが開き、このウィンドウにも表示されます。このコンピューターの同じパスのファイルは読み取りません。その形式の既定のハンドラをリモートで使えない場合は、リモートで使えるハンドラだけを選択肢として表示し、そのようなハンドラがない形式は案内だけを表示します。
- Markdown サーフェスではリモート文書の内容がこのコンピューターのテーマで表示され、アドレスバー左側の **再読み込み** <!-- en: Reload --> ボタンを押すと最新の内容を再取得します。リモートで文書が変更されても内容は自動で変わらず、再読み込みボタンがアクセントカラーで塗りつぶされます（リモートの Tasty がヘッドレスビルドの場合は色が変わらないため、手動で押して確認してください）。接続が切れて再接続を待っている間は、以前の内容の代わりに接続が切れたことを示す案内が表示され、アドレスバーとボタンはすべて無効になり、ボタンに **リモートとの接続が切れました** <!-- en: Disconnected from the remote --> と表示されます。再接続すると最新の内容を自動で取得します。リモート文書内の相対パスの画像とファイルリンクは開けません。
- リモート Markdown のアドレスバーにリモートコンピューターのパスを入力し、`Enter` または **移動** <!-- en: Go --> を押すと、同じサーフェスがそのリモートファイルに切り替わります。このコンピューターの最近使ったファイル一覧は自動補完に表示されません。`Esc` を押すと、入力が現在の文書のリモートパスに戻ります。開けない場合は入力したパスがそのまま残り、アドレスバーの下に理由が表示されます。リモートにそのファイルがない場合は **リモートで … を開けません: ファイルが見つかりません。** <!-- en: Can't open … on the remote: file not found. -->、リモートが別の理由で拒否した場合は、リモートから送られた英語の理由がそのまま付きます。リモートが応答する前に接続が切れると、**リモートの応答前に接続が切れました。再接続してからもう一度お試しください。** <!-- en: Connection lost before the remote answered. Reconnect and try again. --> と表示されます。このとき、リモートで変更されたかどうかは不明なため、再接続してから確認してください。30 秒経っても応答がない場合は、アドレスバーの下に **リモートの応答を待っています…** <!-- en: Still waiting for the remote… --> と表示され、リモートが遅れて応答してもその結果が反映されます。再び入力するか `Esc` を押すとこれらの行は消え、その後に遅れて届いた失敗は再表示されません。遅れてでも開いた場合は、文書がそのファイルに切り替わります。
- リモート Markdown のアドレスバー左側のフォルダーボタン（**リモートのファイルを開く…** <!-- en: Open a remote file… -->）は、リモート文書があるリモートフォルダーでファイル選択画面を開きます。選んだリモートファイルが同じサーフェスに開き、リモートで開けない場合はトーストで通知します。
- ミラーを表示中に **マークダウンファイルを開く** <!-- en: Open Markdown File --> ポップアップでサーフェスを Markdown に変換したり新しいタブを開いたりする場合、ポップアップに入力したパスや **参照…** <!-- en: Browse… --> で選んだパスは、リモートコンピューターのファイルとして開きます。相対パスはリモートターミナルの現在のフォルダーが基準です。この方法で開いたファイルは、このコンピューターの最近使ったファイル一覧には残りません。
- Linux、Windows、macOS では、リモート HTML ファイルの本文を表示できます。大きなファイルを受信する前に **許可** または **拒否** を選んでください。スクリプトは手元のコンピューターの HTML 設定に従い、許可すると受信済みの本文で再表示します。アドレスは読み取り専用で、**再読み込み** で最新の本文を取得します。接続が切れると受信済みの本文は残り、再読み込みは無効になります。古いバージョンとの接続では空の領域のままになることがあります。相手側も対応していれば、同じフォルダー以下の CSS・画像などの別ファイルも受信します。大きなファイルが複数ある場合は 1 つずつ確認し、総受信量の 2MB 制限に達すると **続行** または **中止** を選びます。大きなファイルの確認と累積量の確認は、長時間待っても消えません。待っている間にリモートの転送が期限切れになった場合は、**許可** または **続行** を押すとそのファイルを再要求し、その間にファイルサイズが変わっていればもう一度確認します。続行では残りのファイルも引き続き受信し、再読み込みでは失敗したファイルも再要求します。拒否したファイルや受信できなかったファイルの数は、再読み込みするまで残ります。下位の HTML に移動すると、新しい文書として検査します。ページがファイル要求をキャンセルすると受信待ちも解除し、同じファイルを受信するほかの要求は維持します。Linux X11（`DISPLAY` があり X サーバーに接続できる Wayland セッションの XWayland を含みます）、Windows、macOS 27 以降では、双方のバージョンが対応していれば HTTP・HTTPS のウェブアドレスも開けます。要求はリモートコンピューターで実行するため、ウェブページのフォーム送信やボタンがリモートサービスの状態を変えることがあります。ただし、Windows と macOS では、スクリプトを許可したページの WebRTC 接続がこのコンピューターから直接外部に接続することがあります。Tasty はページの WebRTC 機能を削除してこれを減らしますが、すべての経路を遮断する保証はありません。同じサイトへの要求は既定で許可し、ほかのサイトへの要求は手元の HTML リモートコンテンツ設定に従います。ブラウザーのセキュリティポリシーも維持されます。各応答の転送サイズ 100000 バイト、文書全体 2000000 バイトで、既存の受信同意を求めます。スクリプトの許可は受信済みの本文で再表示し、フォームを再送信しません。明示的な再読み込みは元の要求を再送信し、同じ文書の Cookie を維持します。接続が切れるとスクリプトを停止し、再接続したりリモートアドレスが変わったりしても Cookie とスクリプトの許可は引き継ぎません。このとき、専用ブラウザーストレージを準備する処理が一時的に重なると、限られた時間だけ待機し、ストレージ上限や安全性検査の失敗はエラーとして表示します。macOS では、リモートコンピューターの `localhost`・`127.0.0.1` などのアドレスを `localhost.tasty.localhost` のような別名で開きます。画面に表示されるアドレスは元のアドレスですが、ページのスクリプトが読み取るアドレスはこの別名で、文書内でリモートの `localhost` を完全なアドレスで指定した画像・要求は開けません。相対パスとリンクによる移動はそのまま使えます。`DISPLAY` がない、または X サーバーに接続できないために Linux のネイティブ Wayland で実行している場合と、macOS 11–26 ではリモートウェブアドレスの表示に対応しておらず、このコンピューターから代わりに接続することもありません。macOS の最小対応バージョンは 11 のままです。
- `--raw` はサーフェス単位でのみ使えます。
- ターミナルで実行するアタッチでは、`--no-reconnect` を指定しない限り、SSH が切れると自動で再接続を試みます。
- 回線が遅く、リモートが送信していた画面の一部を受信し損ねると、リモートがそのことを通知し、アタッチが自動で再アタッチして画面を再取得します。その際、ターミナルに案内が 1 行表示されます。画面を出力して終了するアタッチは、1 回の実行で最大 3 回再アタッチし、それでも受信し損ねた場合は結果を出力してから画面の一部が欠けている可能性を通知します。`--raw` は回数制限なしで再アタッチし、画面を最初から再描画します。`--send` で送信した入力は再送信しません。

CLI から実行中の Tasty ウィンドウに直接アタッチするには、上記の `--into-gui` を使ってください。再起動後も残す接続については、下の保存されたリモート行を参照してください。

## 5. 保存されたリモート行に接続する

**リモートワークスペースを追加** <!-- en: Add remote workspace --> ダイアログからアタッチしたワークスペースは、接続情報と行の名前・カテゴリ・位置が保存されます。再起動後も同じ場所に戻り、画面に表示されるとすぐに接続を試みます。再起動後に復元されたアクティブな行、ウィンドウのフォーカス切り替え、行の選択も対象です。手動で切断した行と、別の場所で閉じられた行は除きます。CLI でアタッチしたミラーは保存されず、切断時に削除されます。

保存された行の接続が途切れると、**再接続の試行時間** <!-- en: Keep reconnecting for --> の間は再接続を試み、その後は切断状態で一覧に残ります。既定値は 300 秒、範囲は 0〜3600 秒です。0 では自動再接続せず、すぐに切断状態になります。再接続の開始・成功・タイムアウトは、トーストではなく接続ポップアップとカード・状態表示で知らせます。別のクライアントが占有中、リモートワークスペースが存在しない、接続先がミラーの場合は、すぐに再接続を停止して理由を示します。初回の接続に失敗した行は理由を残し、その行に戻るか接続を要求するまで自動で再試行しません。

手動で切断した行のポップアップには **切断済み** <!-- en: Disconnected --> と「手動で切断したワークスペースです。再接続するまで切断状態が続きます。」が表示されます。別の行に移動して戻るだけでは接続されません。ポップアップや行メニューで接続・再接続を選ぶか、**リモートワークスペースを追加** <!-- en: Add remote workspace --> ダイアログで同じ行を選んでください。エージェントは次のコマンドで明示的に接続します。

```sh
tasty list workspaces
tasty remote connect --workspace 7
```

`--workspace` は必須で、保存されたリモート行の **ローカル ID** を指定します。例の `7` は `tasty list workspaces` で調べた行の ID で、リモート ID ではありません。接続してもフォーカスは移動しません。受付応答を JSON 1 行で出力し、最終結果を 2 行目の JSON で出力します。接続済みの行はすぐに成功し、接続中の行は進行中の試行に合流します。結果が失敗、または 90 秒以内に届かなければ終了コード 1 で終了します。通常のローカルワークスペース、保存されていない CLI ミラー、存在しない ID、リモートワークスペースがなくなった場合、行のウィンドウが閉じている場合はすぐに失敗します。

`tasty claude spawn --workspace` のようにワークスペースを指定する要求を未接続の保存された行に送ると、接続を開始して最大 35 秒待ちます。再起動後にまだ接続していない行にはペイン・タブ・サーフェスがないため、ワークスペース引数を受け取る要求だけが対象にできます。サーフェスを指定する `tasty send`・`tasty read screen` などは、今回の起動中に接続し、サーフェスが残っている行だけで使えます。接続できれば要求を実行し、接続できないか拒否された場合は理由を示すエラーで終了します。ただし、手動で切断した行では切断状態のエラーとなり、要求は実行されません。エラーの案内に従い、`tasty remote connect --workspace <id>` または行の接続メニューで先に接続してください。同じリモート接続先に `tasty remote attach --into-gui` を送っても、手動の切断は解除されません。

`tasty list workspaces`、`tasty remote workspaces`、`tasty remote refusals` で一覧を取得するだけでは接続しません。`tasty list workspaces` の通常出力には `[mirror]` の印がありますが、接続状態は表示されないため、保存された行の接続状態は GUI のポップアップとカードで確認してください。

別の場所でリモートワークスペースが閉じられた行は残りますが、再選択しても接続せず、再接続ボタンも無効になります。Tasty を再起動すると未接続の行に戻り、接続を再び要求できます。

## ミラー内でできること

- キー入力・マウス操作はそのままリモートターミナルに送られます。サイズは手元のペインのサイズに合わせてリモートが再配置します。
- リモートが新しいサイズに応答しない場合、Tasty がもう一度要求します。それでも応答がない場合（約 10 秒）は、ワークスペースの上に **リモートと端末サイズを同期できませんでした** バナーが表示され、該当するタブ名が表示されます。分割したタブのように同じ名前のタブが複数ある場合は、名前を一度だけ表示し、`Shell ×2` のように個数を付けます。**再試行**（複数の場合は **すべて再試行**）で再要求でき、× はバナーだけを閉じます。後からでもリモートがそのサイズを受け入れると、バナーは自動で消えます。リモートがこの機能のない古いバージョンの Tasty の場合、バナーは表示されません。
- 分割、新しいタブ、タブを閉じる・並べ替える操作、サーフェスの変換、閉じた項目の復元は**リモートで実行**され、結果がミラーに反映されます。リモートにない種類のサーフェスを作成すると、トーストで失敗を通知します。エージェントが要求した分割・新しいタブ・閉じる・移動・変換（Markdown 文書の移動と画像を開く操作を含む）と、エージェントが開く場所を指定せずに要求したファイルを開く操作がリモートで失敗した場合は、トーストなしでログにだけ残ります。
- サーフェスの右クリックメニューの **サーフェスを移動** は、同じミラーワークスペース内に限りリモートで実行されます。ミラーとほかのワークスペースの間での移動はブロックされます。
- タブの右クリックメニューの **タブを移動**・**ペインを移動** による移動はミラーでは使えません。移動する側か移動先がミラーの場合は、ブロックしたことを示すトーストだけが表示され、何も変わりません。
- ミラー内で **閉じた項目を復元**（既定は `Ctrl+Shift+T`）を押すと、リモートで閉じたタブが復元されます — そのタブはリモートターミナルなので、入力もリモートに送られます。復元されたタブの以前のスクロールバックは、リモートウィンドウでのみすべて表示されます（ミラーは表示中の画面から受信します）。
  - エージェントが CLI でミラー内のタブを閉じた場合は復元されません — リモート側のウィンドウで復元を押しても同様です。復元は、人が手動で閉じたものだけが対象です。
  - 復元は、**そのリモートワークスペースで閉じたもの**だけを復元します。リモートに復元するものがない場合は案内トーストだけが表示され、何も起きません — 手元で閉じたタブが代わりにミラー内に作成されることはありません。手元のワークスペースに戻って同じキーを押すと、そのときに手元のものが復元されます。
- リモートでシェルが終了して（`exit`）閉じたタブは、ミラーからも直ちに消えます。
- リモートターミナルの完了・入力待ちの表示（枠線・バッジ）も、そのままミラーに届きます。
- リモートが送信していた画面の一部を受信し損ねると、「リモート画面の一部を受信できませんでした」 <!-- en: Part of the remote screen was lost --> トーストが表示され、ミラーが自動で再アタッチして画面を再取得します（プロファイルなしでアタッチしたミラーも同様です）。再アタッチ後は、スクロールバックに同じ画面がもう一度追加されることがあります。クリップボード画像のアップロード中にこれが起きると、アップロードは失敗として終了し、再試行できます — リモートにすでに保存されている可能性があるため、自動では再送信しません。
- クリップボード画像を貼り付けるとリモートにアップロードされ、**リモートパス**が入力されます。テキストは、以下の場合を除いてそのまま入力されます。
  - 手元のターミナルでキャプチャすると、手元のクリップボードにローカルのファイルパスと画像が入ります。リモートはこのローカルパスを読み取れません。ミラーのターミナルで貼り付けのショートカットを押すとき、テキストが手元のキャプチャフォルダー `~/.tasty/screenshots/` の直下にあるファイルのパスで、クリップボード画像を読み取れる場合は、画像をリモートにアップロードしてリモートパスを入力します。キャプチャ時に画像を追加できずパスだけがコピーされた場合など、画像を読み取れない場合は、ローカルパスをそのまま入力します。
- ミラー内で [スクリーンショットをクリップボードへ](../using/terminal.md#スクリーンショットをクリップボードへ)（`Ctrl+Alt+S`）を押すと、画面は手元のコンピューターでキャプチャし、ファイルはリモートに保存してから、**リモートクリップボード**にリモートパスと画像を一緒に入れます。手元のクリップボードは変わりません。リモートの Tasty が画像のコピーに対応していない古いバージョンの場合は、パスだけが入り、トーストでそのことを通知します。リモート接続がなく送信できない場合は、ファイルが手元のコンピューターにだけ保存されたことを通知し、リモートの応答前に接続が切れた場合は、コピーを確認できなかったことを通知します。
  - 貼り付けのショートカットは手元のクリップボードを読み取ります。ただし、キャプチャ後に手元で別の内容をコピーしていなければ、同じミラーのターミナルでは、手元の内容の代わりにリモートの `~/.tasty/screenshots/` に保存されたファイルのパスを入力します。別の内容をコピーしていれば、通常どおりその手元の内容を入力します。
  - 同じパスを繰り返し貼り付けられます。そのミラーで新しく撮影すると、以前のスクリーンショットに代わって使われます。そのミラーワークスペースがウィンドウから消えると、この方法では貼り付けられなくなります。
  - リモートが保存先のパスを返す前や、応答にパスがない場合は、手元の内容を入力します。ファイルが保存されてパスが返されれば、リモートクリップボードへの書き込みだけが失敗してもリモートパスを入力します。
  - キャプチャ前とまったく同じ内容をコピーし直すと、変更されていないものとしてリモートパスを入力します。キャプチャ直前に手元のクリップボードを読み取れなかった場合、そのスクリーンショットはこの方法では貼り付けられません。リモートデスクトップ（RDP）クライアントなどがリモートクリップボードを手元のクリップボードにコピーした場合、貼り付けのショートカットは、そのコピーされた手元の内容を入力します。
- ミラーワークスペースの番号を `--workspace` に指定すると、`tasty claude spawn`・`tasty codex spawn` の子がリモートコンピューターで実行され、手元ではそのミラー内の子として扱います。使い方は [Claude · Codex](../agents/claude-codex.md#接続したリモートワークスペースに子を作成する) にあります。
  - 接続が切れている間、その子の状態は `unknown` と表示されます。同じリモートの Tasty に再接続すると、その間に発生した完了が一度配信されます。
  - リモートの Tasty が再起動すると、それ以前に作成した子の完了は配信されません。リモートの古いバージョンの Tasty には子を作成せず、エラーを通知します。
- ミラーサーフェスのシェルを再生成する操作（`tasty surface respawn-terminal`、`tasty terminal respawn`）や、バックグラウンド PTY をミラー内にタブとしてアタッチする操作（`tasty pty attach-surface`）も拒否されます。リモートターミナルの場所に手元のシェルが混ざるためです。リモートインスタンスで直接実行してください。
- ミラーワークスペースへのタブ・ペインのプリセット適用（プリセットポップアップ、`tasty preset apply`）も、同じ理由で拒否されます。ワークスペースのプリセットは新しいワークスペースを作成するため、そのまま使えます。

## ミラーを閉じる操作と接続の切断

保存されたリモート行を右クリックすると、次の項目が表示されます。

- **接続を切る** <!-- en: Disconnect --> — 接続と進行中の接続・再接続の試行を終了し、行は残します。リモートワークスペースとプログラムは実行を続け、リモート側から再び入力できます。再利用するには明示的に接続してください。
- **ローカルで閉じる** <!-- en: Close locally --> — この Tasty から行を削除し、進行中の接続試行を取り消します。リモートワークスペースとプログラムは残ります。ワークスペースを閉じるショートカットも、保存された行ではローカルで閉じる操作になります。
- **リモートワークスペースを閉じる…** <!-- en: Close remote workspace… --> — 接続済みの状態で確認ダイアログを開き、リモートワークスペースと全プログラムを終了します。取り消すことはできず、成功すると保存された行も消えます。接続済みの保存された行で最後のタブ・ペイン・サーフェスを手動で閉じる場合も、リモートを閉じる確認が表示されます。エージェントによる閉じる要求は確認なしで実行されます。

CLI でアタッチした保存されていないミラーのカードメニューには、**ワークスペースの接続を切る** <!-- en: Disconnect Workspace --> と **ワークスペースを閉じる** <!-- en: Close Workspace --> があります。前者はリモートの作業を残して手元のミラーを削除し、後者はリモートワークスペースとプログラムを終了します。最後のタブ・ペイン・サーフェスを閉じる操作もリモートワークスペースを閉じます。リモートの最後のワークスペースを閉じると、リモートウィンドウに新しいターミナルワークスペースが作成されます。

リモートワークスペースを閉じる場合、リモートが閉じたと応答した後にだけ手元のミラーを削除し、**リモートの Tasty でワークスペースを閉じました。** <!-- en: Closed the workspace on the remote Tasty. --> と表示します。リモートが拒否するとミラーは残り、失敗の案内が表示されます。手動でリモートを閉じたワークスペースは、保存された行か未保存のミラーかを問わず、リモートウィンドウの閉じた項目の復元から戻せます。ただし、実行中だったプログラムは戻りません。

保存されていないミラーの接続を切り、それが最後のワークスペースだった場合、手元のウィンドウは閉じず、新しいターミナルワークスペースを開きます。保存されたリモート行は接続を切っても残ります。

接続処理中や再接続中はリモートを閉じる要求を送れません。リモートの Tasty が対応していない場合は更新するか、接続だけを切ってください。応答前に接続が切れた場合は、閉じたかどうか不明と案内されます。リモートでまだ実行中の可能性があるため、再接続して確認してください。

CLI でもリモートの作業を残して接続だけを切れます。

```sh
tasty remote disconnect --workspace 7
```

`--workspace` には `tasty list workspaces` の `[mirror]` 行の **ローカル ID** を指定します。保存された行は一覧に残るため、`tasty remote connect --workspace <ローカル id>` で再接続します。保存されていないミラーは `tasty remote attach --into-gui --workspace <リモート id>` で再びアタッチします。保存された行は未接続でも切断コマンドが成功し、進行中の試行を取り消します。

これはリモートウィンドウの **強制切断** とは異なります。強制切断はリモートコンピューターから他の人の接続を解除する操作です。

## 占有の解除（リモート側で）

自分の Tasty のワークスペースが別の場所からアタッチされて読み取り専用になると、サーフェスに **強制切断** <!-- en: Force detach --> の案内が表示されます。この案内はそのワークスペースを表示しているときだけ出るため、サイドバーから直接切断することもできます — 占有中のワークスペースカードを右クリック > **強制切断** <!-- en: Force detach --> を押すと、画面中央に確認ポップアップが表示され、確認するとその場で解除されます。そのワークスペースに切り替える必要はありません。

別の人の接続を切る CLI コマンドはありません。サーバーのエージェントがリモートで作業中の人を誤って切断しないよう、画面からだけ切断します。画面なしで実行した Tasty のように GUI がないサーバーでは、リモート側が入ってきた SSH セッションを終了すると、接続が閉じて占有が解除されます。リモート側が自動で再接続すると、再アタッチされることがあります。

リモート側のユーザーがアタッチしている間、そのワークスペースでローカルから分割・タブ作成・`spawn` を行ったり、CLI でタブ・ペインのプリセットを適用したり（`tasty preset apply`）、バックグラウンド PTY をタブとしてアタッチしようとすると（`tasty pty attach-surface`）、「占有中」エラーで拒否されます。別のワークスペースを使うか、強制切断してから進めてください。

## リモートから受け取ったファイルの保存先

アタッチチャネルで転送されたファイルは `~/.tasty/transfers/` に保存され、フォルダーの上限は 500 MiB です。**設定** > **一般** > **リモート転送** <!-- en: Remote transfer --> または CLI で変更してください。

```sh
tasty settings get-remote-transfer
tasty settings set-remote-transfer --dir ~/Downloads/tasty --max-mb 2000
```

CLI アタッチの `--raw` 出力を別のコマンドに渡したとき、そのコマンドが先に終了すると、アタッチも正常終了します。
出力デバイスの権限の問題など、ほかの書き込みエラーは失敗として通知します。

## 応答がない場合に接続を切断するまでの時間

リモートアタッチ接続では、相手から何も受信しないまま設定した時間が経過すると、接続を切ります。既定の待機時間は以前の固定時間より長くなり、30 秒になりました。**設定** <!-- en: Settings --> › **一般** <!-- en: General --> › **リモートアタッチ** <!-- en: Remote attach --> で、**アタッチ接続** <!-- en: Attach connections --> の下にある **切断までの待機時間** <!-- en: Disconnect after --> を変更できます。単位は秒で、10〜600 秒の範囲で設定します。

設定を保存すると、再起動せずに新しい接続から適用され、すでに開いている接続はそのままです。双方の Tasty はそれぞれ自分の値を使うため、片方の時間を延ばしても相手が先に切断することがあります。設定ファイルを読み込まない CLI アタッチは 30 秒を使います。設定ファイルのキーと範囲外の値の扱いについては、[設定](../customize/settings.md) を参照してください。

**設定** <!-- en: Settings --> › **一般** <!-- en: General --> › **リモートアタッチ** <!-- en: Remote attach --> の **再接続の試行時間** <!-- en: Keep reconnecting for --> は、保存されたリモート行の接続が切れた後に自動再接続を試みる時間です。既定値は 300 秒、範囲は 0〜3600 秒で、0 は自動再接続を無効にします。手動で切断した接続には適用されません。設定ファイルのキーは `[remote_attach] reconnect_timeout_secs` です。

## 応答を待っている間

ミラーで新しいタブや分割を作成すると、次の画面からその場所を先に表示します。サーバーが確定するまで新しい領域に入力は送れませんが、既存のタブや領域を選んで作業を続けられます。待機中に別の場所を選んだ場合は、遅れて完了しても選択を元に戻しません。失敗した要求の一時領域だけが消えます。

200ms 以上応答を待つと、タブとサイドバーにスピナーが表示され、作業領域の右上に **応答待ち** <!-- en: Waiting for response --> と経過時間が表示されます。要求が複数ある場合は、件数と最も長く待っている時間を表示します。ポインターを合わせると、要求の種類ごとに最も長く待っている時間を 1 行ずつ確認できます。閉じる・移動・復元・変換や、フォルダー・文書・Git の照会も応答を待っている間は表示し、画面や入力をブロックしません。Native WebView は非表示にせず、タブとサイドバーの表示を使います。

スピナーはタブアイコン、サイドバーのステータス点、折りたたんだサイドバーのアバターの位置だけに表示され、タブタイトルやワークスペース名は変わりません。待機中のタブやワークスペースにポインターを合わせると、名前の下に **接続中…** <!-- en: Attaching… --> も表示されます。

通常の入力の待機表示は、これに対応するサーバーが先行する入力をアプリの処理境界まで渡したかどうかを確認します。シェルコマンドやプログラムが終了したという意味ではありません。出力のない正常な入力や長時間実行するコマンドのために表示を続けることはなく、古いサーバーには未対応の入力確認を待ちません。接続が切れると、保存された行は接続ポップアップと印で状態を示し、保存されていない CLI ミラーは削除されます。

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| `kind='ssh'` の拒否 | `--profile` に ssh プロファイルを指定しています。`tasty-attach` プロファイルを作成して指定してください |
| リモートの tasty が見つからない | リモートで Tasty が実行中か確認してください。`tasty tool remote-profile detect --name <n>` でポートを検証してください。PATH にない場合は実行ファイルのパスを指定するか、`--port-mode file-unix` を使ってください |
| タイムアウト | ホストに接続できるかと、ファイアウォールの設定を確認してください。ssh プロファイルの `--option ConnectTimeout=<秒>` |
| SSH 接続失敗 | 認証・ホストキー。まず `tasty tool ssh <ssh プロファイル>` で接続できるか確認してください |
| この Tasty 自身を指しているという案内・エラー | プロファイルのホスト（ホスト名・LAN IP を含む）とポートファイル、または `--into-gui --target-port` で指定したポート（自分で開いた SSH トンネルを含む）が、現在使っているこの Tasty を指しています。自分自身にはアタッチできません。同じコンピューターの別の Tasty にアタッチするには、そのインスタンスのポートファイルを指定してください |
| `--into-gui` がこのビルドでは未対応というエラー | コマンドを受け取ったローカルの Tasty は、ウィンドウなしで実行される [ヘッドレスビルド](../getting-started/install.md#ヘッドレスビルド) です。ミラーを表示するウィンドウがないため、要求を受け付けません。GUI で実行中の Tasty に送信してください |
| Tasty を強制終了した後に `ssh` プロセスが残る | macOS では正常終了（メニューからの終了・ウィンドウを閉じる操作）のときだけ、リモートアタッチトンネルを整理します。強制終了・異常終了後に残った `ssh -N -L` プロセスは手動で終了してください。Linux・Windows では Tasty が終了すると一緒に終了します |
| ワークスペースのアタッチ拒否 | 中のターミナルの 1 つがすでに別のクライアントに占有されています。リモートで強制切断してください |
| 最初のアタッチ時に画面が一瞬ちらつく | リモートが手元のペインサイズに再配置する間の正常な動作です |
