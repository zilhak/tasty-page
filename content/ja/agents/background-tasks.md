# バックグラウンドタスクをタブに取り込む

Tasty では、タブのない非表示の PTY でタスクを実行し、同じプロセスと履歴を維持したままタブに取り込めます。タブに取り込む前でも出力を確認できます。

<!-- tasty-diagram: background-task -->
```
読んでいるログ: そのまま | 実行中の非表示の PTY: 新しいタブに取り込む
```

## 準備

Tasty ウィンドウを開き、その中のターミナルで以下のコマンドを実行してください。`tasty` コマンドが接続できない場合は、先に [CLI の準備](cli.md#準備)を確認してください。

ここで扱うのは、実行中の Tasty 内にある **タブのない PTY** です。GUI なしでサーバー上で Tasty 自体を実行するヘッドレスビルドとは異なります。

以下の入力例は Bash、Zsh、Git Bash を前提としています。数値 `2147483648` とペイン ID `1` は例なので、必ず実際の応答で確認した値に置き換えてください。

## 1. タブなしでシェルを開く

```sh
tasty pty spawn
tasty pty list
```

作成時の応答にある PTY ID を記録してください。新しい PTY は一覧に表示されますが、画面にタブは作成されません。コマンドなしで起動したため、シェルは入力を待っています。

開始するフォルダーと最初に実行するコマンドを一緒に指定することもできます。

```sh
tasty pty spawn --cwd ~/proj -- cargo test
```

`--cwd` は PTY の作業フォルダーを指定します。`--` の後の内容は PTY のシェルですぐに実行されます。

## 2. コマンドを送って出力を読む

```sh
tasty pty write --id 2147483648 $'pwd\n'
tasty pty read --id 2147483648 --lines 20
```

`read` はデフォルトで、薄く表示される文字（例: Claude Code の自動補完候補）を除いて読み取ります。未送信の候補を実際の出力と誤解しないようにするためで、一緒に読み取るには `--show-dim` を付けてください。

`write` は受け取った文字をそのまま送信します。Bash 系の `$'...\n'` は実際の改行を含むため、コマンドが送信されます。通常の二重引用符内の `"...\n"` とは異なります。

PowerShell で実行する場合は、入力コマンドを次のように記述してください。

```powershell
tasty pty write --id 2147483648 "pwd`n"
```

出力に作業ディレクトリが表示されることを確認してください。まだ出力がない場合は、`read` でもう一度確認します。同じ方法で必要なタスクを実行できます。

## 3. 実行状態を確認する

```sh
tasty pty state --id 2147483648
```

`state` は終了するまで待機せず、現在終了しているかどうかを即座に返します。待つには再度呼び出してください。以前の名前 `pty wait` も同じ動作で受け付けます。シェルが動作中であれば、`exited` は `false` です。プロセスが終了していれば、終了コードと成功したかどうかも確認できます。

シェル内でコマンドが 1 つ終了しても、シェル自体が終了したわけではありません。PTY の終了状態と個々のシェルコマンドの結果を区別してください。

## 4. 同じタスクをタブで見る

```sh
tasty list panes
tasty pty attach-surface --pty 2147483648 --pane 1
```

一覧から選んだペイン ID を使用してください。**まだ実行中の PTY のみ**取り込めます。プロセスと出力履歴を維持した新しいバックグラウンドタブが作成され、元の PTY ID は `pty list` から除かれます。

取り込みに失敗した場合、プロセスは終了せず、元の PTY ID に戻ります。まれに元の ID に戻せない場合は、復旧が必要なエラー（`-32068`）が返され、そのプロセスは `pty list` に表示されないまま Tasty が終了するまで残ります。

表示中の画面は自動では切り替わりません。見たいときに新しいタブを直接選択してください。切り替えの応答には新しいタブとサーフェスの ID が含まれるため、以降の CLI 操作にはその ID を使用します。以前の PTY ID で `pty read` や `pty kill` を呼び出さないでください。

## 5. タスクを片付ける

- まだ非表示の PTY であれば、実際の ID で `tasty pty kill --id 2147483648` を実行してください。該当するプロセスを終了し、非表示の PTY 一覧から削除します。
- タブに取り込んだ場合は、タスクを終えた後にそのタブを閉じてください。非表示の PTY 一覧で片付ける対象ではありません。

非表示の PTY の数に制限はなく、すでに終了した PTY が残っていても新しい PTY を作成できます。同時に実行する数を調整したい場合は、[タスクの順序管理](tasks.md)の semaphore を使用してください。

実行中の PTY は、長時間確認しなくても Tasty が終了させることはありません。直接 `kill` するまで実行されます。一定時間確認しなければ終了させたい場合は、作成時に `--idle-timeout <秒>` を指定してください。その時間内に `read`、`write`、`state` がなければ、Tasty がプロセスを終了して警告通知を残します。バックグラウンド出力でこの時間が延長されることはありません。

すでに終了した PTY は、終了コードを確認できるように一覧に残ります。Tasty が一覧の整理中に終了を初めて確認した時点と、最後に `read`、`write`、`state` を呼び出した時点のうち、遅い方から 5 分経過すると整理され、整理したことを知らせる情報通知が残ります。Tasty は終了した PTY を定期的に確認するため、初めて確認する時点は実際の終了より最大 1 分 30 秒遅れる場合があります。

## 問題が発生した場合

- PTY が見つからない場合は、`tasty pty list` で確認してください。すでにタブに移動したか、整理された可能性があります。Tasty が整理した PTY であれば、エラーメッセージでアイドル制限の期限切れか、終了した PTY の整理かが示され、通知にも残ります。
- 終了した PTY はタブに取り込めません。出力と終了状態を確認してから片付けてください。
- 入力が実行されない場合は、実際の改行を送信したか確認してください。

通常の子ターミナルと出力の読み取り機能については [CLI ガイド](cli.md)、タスクの依存関係と失敗時の処理については[タスクの順序管理](tasks.md)に記載されています。
