# 工作区

Tasty 的工作区将项目或任务所用的终端和布局归为一组，通过名称和分类区分，并可在侧边栏中切换。

## 创建

| 方法 | 操作 |
|------|------|
| 侧边栏最下方的**新建工作区** <!-- en: New Workspace --> 按钮 | 创建包含一个终端的工作区 |
| `Alt+N`（macOS `Cmd+N`） | 相同操作 |
| 右键点击**新建工作区**按钮 > **从预设创建工作区...** <!-- en: Create workspace from preset... --> | 使用已保存的布局预设创建（[保存布局](panes-tabs-splits.md#保存布局预设)） |
| 右键点击侧边栏空白处 > **添加远程工作区** <!-- en: Add remote workspace --> | 镜像另一台计算机上的 tasty（[继续远程工作](../remote/attach.md)） |

新工作区的终端从当前终端的工作目录启动（**设置** > **终端** <!-- en: Terminal --> > **继承工作目录** <!-- en: Inherit working directory -->，默认开启）。

要以终端以外的 Surface 启动，或在创建时指定名称，使用 CLI。

```sh
tasty new workspace --name build --cwd ~/proj
tasty new workspace --type explorer --path ~/proj
tasty new workspace --type markdown --file README.md
```

## 名称和副标题

默认名称为 `Workspace 1` 这样的序号。右键点击侧边栏卡片即可更改。

- **重命名** <!-- en: Rename --> — 快捷键 `F3`。
- **更改副标题** <!-- en: Change Subtitle --> — 卡片下方的小字。快捷键 `F4`。

```sh
tasty set workspace --id 3 --name api --subtitle "port 8080"
tasty list workspaces
```

## 切换

- 点击侧边栏卡片。
- `Alt+1` ~ `Alt+9`（macOS `Cmd+1` ~）。按住 `Alt` 时，卡片旁会显示数字键帽，标明对应编号。
- `Alt+J` / `Alt+K` — 下一个 / 上一个工作区。到达末尾时循环到另一端。
- 通知面板中的**跳转** <!-- en: Jump --> 按钮 — 跳转到发送通知的 Surface 或工作区。来源已关闭时，按钮禁用。

修饰键和数字键可在**设置** > **按键绑定** <!-- en: Keybindings --> 的**工作区切换修饰键** <!-- en: Workspace switch modifier --> 项中更改。

每个工作区单独记住获得焦点的窗格。切走再返回时，光标仍在原处。切换时，侧边栏列表自动滚动，使活动卡片可见。

## 调整顺序

- 拖动卡片。
- 右键点击卡片 > **上移** <!-- en: Move Up --> / **下移** <!-- en: Move Down -->。
- `tasty move workspace --id 5 --to 0` — **按 ID** 指定要移动的工作区。即使有多个窗口，也会在拥有该 ID 的窗口中移动。ID 显示在 `tasty list workspaces` 中。
- `tasty move workspace --from 2 --to 0`（从 0 开始计数）— 序号是**窗口内的位置**，有多个窗口时，会在当前查看的窗口中移动。

## 卡片上的标记

| 标记 | 含义 |
|------|----|
| 名称左侧的圆点 | 该工作区中有程序正在运行（同时显示数量，如 `● 3`） |
| 名称右侧的数字徽标 | 需要查看的 Surface 数量。黄色表示等待输入，蓝色表示任务已结束。点击对应 Surface 后消失 |
| **远程** <!-- en: REMOTE --> 胶囊标记 | 镜像远程 tasty 的工作区 |
| 名称左侧圆点周围的淡紫色边框 | 正被其他用户远程占用 |

折叠侧边栏时（**折叠** <!-- en: Collapse -->，`Ctrl+B`），卡片变为正方形图标，标记也随之缩小。右上角圆点只用颜色表示最紧急的一项，不显示数量 — 黄色表示等待输入，蓝色表示任务已结束，绿色表示正在运行。**远程**胶囊标记变为右下角的天蓝色小标记。被其他用户远程占用时，淡紫色边框围住**整个正方形图标**，而非圆点。

## 关闭和恢复

- 右键点击卡片 > **关闭工作区** <!-- en: Close Workspace -->，或按 `Alt+Shift+W`。
- 远程镜像卡片还会显示**断开工作区连接** <!-- en: Disconnect Workspace -->。在镜像中，**关闭工作区**会关闭远程计算机上的工作区，断开连接则保留远程工作区，仅关闭本地镜像（[关闭镜像和断开连接](../remote/attach.md#关闭镜像和断开连接)）。
- `Ctrl+W` 对应**关闭活动项** <!-- en: Close active --> — 只剩一个标签页时关闭窗格，只剩一个窗格时关闭工作区。

如果包含正被远程附加使用的终端，则不会关闭，而是显示提示。此时有人正在该终端
中工作，关闭会导致其会话在没有预告的情况下结束。要收回
占用，点击占用标记上的**强制分离** <!-- en: Force detach --> 后再次关闭。
如果不想切换到该工作区，也可以右键点击侧边栏卡片 — 仅在被占用时
显示**强制分离** <!-- en: Force detach --> 项，点击后会经过一次确认弹窗。

按 `Ctrl+Shift+T` 可从最近的项目开始，恢复手动关闭的工作区、窗格、标签页和 Surface。最多保留 10 条恢复记录，正常重新打开同一布局槽位时，记录也会保留。终端历史记录按内容恢复设置恢复。Shell 会重新启动，若有已保存的会话恢复命令，则执行该命令。通过 CLI 关闭的项目不会加入此恢复列表。

关闭项目时，其终端历史记录保存在 64 MiB 的待处理请求预算内，需扣除其他待处理请求及关闭记录本身占用的空间。因此，即使回滚缓冲区小于 64 MiB，如果超出剩余预算，也会将该终端以不含回滚缓冲区的形式加入恢复列表，并继续关闭。此时通知面板中会留下一条警告；如果在通过远程附加打开的工作区中执行关闭，发起关闭的窗口会显示一次警告提示。恢复省略了内容的终端时，会在相同目录中以空回滚缓冲区打开，一同保留的其他终端的历史记录则按内容恢复设置恢复。此警告不表示运行中的布局和内容保存已全部中断。

## 按分类（文件夹）分组

工作区较多时，开启**设置** > **常规** <!-- en: General --> > **工作区分类（文件夹）** <!-- en: Workspace categories (folders) -->。侧边栏会变为可折叠的分区。

- 默认分区**工作区** <!-- en: Workspaces --> 始终位于最上方，无法重命名或删除。
- 点击分区标题 — 折叠 / 展开。**折叠/展开所有分类** <!-- en: Collapse/expand all categories --> 快捷键默认未设置，需自行指定。
- 右键点击标题 — **添加工作区** <!-- en: Add workspace --> · **从预设创建工作区...** · **添加远程工作区** · **重命名分类** <!-- en: Rename category --> · **删除分类** <!-- en: Delete category --> · **新建分类** <!-- en: New category -->。
- 右键点击空白处 — **新建分类** · **添加远程工作区**。
- 右键点击工作区卡片 — **移至分类** <!-- en: Move to category -->。也可拖到其他分区。
- 删除分类时，其中的工作区不会被删除，而是返回**工作区**分区。

开启分类后，侧边栏下方的**新建工作区**按钮会消失，改用标题菜单创建。`Alt+N` 会在当前工作区所属的分类中创建。

切换快捷键也增加了分类层级。

| 快捷键 | 操作 |
|--------|------|
| `Ctrl+Shift+1` ~ `Ctrl+Shift+0` | 转到第 n 个分类。若已折叠则展开，并转到该分类中上次使用的工作区。按住 `Ctrl+Shift` 时，标题上会显示编号 |
| `Ctrl+Shift+J` / `Ctrl+Shift+K` | 下一个 / 上一个分类 |
| `Alt+1` ~ `Alt+9` | 当前分类**内**的第 n 个工作区 |
| `Alt+J` / `Alt+K` | 当前分类内的下一个 / 上一个。要跨越边界进入下一个分类，开启**设置** > **常规** > **切换到下一个/上一个工作区时包含其他分类** <!-- en: Next/prev workspace crosses categories --> |

再次关闭分类后，所有工作区会合并到同一个**工作区**分区。

```sh
tasty workspace-category list
tasty workspace-category create --name work
tasty new workspace --name api --category work
tasty set workspace --id 3 --category work
```

指定不存在的分类会报错，不会创建工作区，也不会更改名称等属性。

## 重启后恢复

开启**启动时恢复布局** <!-- en: Restore layout on startup --> 后，会重新打开已保存的工作区、窗格、标签页和 Surface 布局。**重启时恢复 Surface 内容** <!-- en: Restore surface content on restart --> 决定是否重新显示终端历史记录。先前运行的程序和环境变量不会按原样恢复。智能体会话仅在已配置集成且存在已保存的恢复命令时重新连接。

当前布局保存在 `~/.tasty/structure/journal.db` 中。旧版本的 `layouts/01.json` 等文件仅在首次迁移时读取。如果布局未恢复，按[故障排除中的恢复说明](../help/troubleshooting.md#设置或窗口布局看似被重置时)操作。

重启时只显示一个窗口，其余槽位会在打开新窗口（`Alt+Shift+N`）时恢复。

无窗口运行的 Tasty [无界面构建](../getting-started/install.md#无界面构建)无论此设置如何，都不会保存或恢复布局 — 工作区仅在本次运行期间存在。如果设置已开启，启动时会记录一行警告，说明此情况。

Tasty 已在运行时再次启动，不会启动第二个 Tasty。从应用菜单或启动器启动时，已有窗口会移到前台；在终端中运行 `tasty` 时，会打开一个新窗口，接续下一个空槽位（在 Windows 上，从前台终端启动时，可能会将已有窗口移到前台）。详细行为见[重新运行 Tasty 时](../help/troubleshooting.md#重新运行-tasty-时)。

要单独保留常用布局，将其保存为预设。方法见[保存布局](panes-tabs-splits.md#保存布局预设)。
