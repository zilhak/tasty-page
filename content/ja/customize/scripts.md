# Lua スクリプト

Tasty に登録した Lua スクリプトは、ショートカットで実行したり、ウィンドウ・ワークスペース・タブが開閉するときに自動実行するよう設定したりできます。

使用するスクリプトを登録し、実行するショートカットやイベントを関連付けてください。登録していないファイルは起動時に自動実行されません。

## 登録

**設定** <!-- en: Settings --> > **その他** <!-- en: Misc --> > **スクリプト** <!-- en: Scripts --> で **スクリプトを追加** <!-- en: Add script --> を押してください。

- **ファイル** <!-- en: File --> — `.lua` ファイルのパスです。**参照…** <!-- en: Browse… --> で選ぶこともできます。配置場所は自由ですが、慣例では `~/.tasty/scripts/` です。
- **表示名** <!-- en: Display name --> — 一覧とキーバインド画面に表示される名前です。空欄にするとファイル名が使われます。

登録すると一覧に行が 1 つ追加され、関連付けられたショートカットも表示されます。まだない場合は **未割り当て** <!-- en: Unbound --> です。行から名前の変更や削除ができます。削除すると、関連付けられたショートカットも解除されます。

## キーバインドで実行

**設定** > **キーバインド** <!-- en: Keybindings --> > **スクリプト実行** <!-- en: Run Scripts --> で、登録したスクリプトごとにキーの組み合わせを指定してください。指定した組み合わせを押すと、その場で実行されます。

## イベントによる自動実行

スクリプト行の下にある **自動実行** <!-- en: Auto-run --> の行で、**トリガーを追加…** <!-- en: Add trigger… --> からイベントを選んでください。複数追加でき、追加したイベントはチップで表示され、クリックすると外れます。すべてのイベントを追加済みの場合、**トリガーを追加…** は無効のまま表示されます。

| イベント | タイミング |
|---|---|
| `tasty.startup.post` | tasty の起動が完了した直後 |
| `window.create.post` · `window.delete.post` | ウィンドウが作成されたとき、閉じられたとき |
| `workspace.create.post` · `workspace.delete.post` | ワークスペースが作成されたとき、閉じられたとき |
| `workspace.change.post` | ワークスペースの名前・説明をウィンドウで直接変更したとき |
| `tab.create.post` · `tab.delete.post` | タブが作成されたとき、閉じられたとき |
| `tab.change.post` | タブの名前をウィンドウで直接変更したとき |
| `pane.create.post` · `pane.delete.post` | ペインが作成されたとき、閉じられたとき |
| `surface.create.post` · `surface.delete.post` | サーフェスが作成されたとき、閉じられたとき |

名前変更の 2 種類のイベントは、**ウィンドウで直接名前を変更したときだけ**発生します。CLI で名前を変更しても、これらのイベントは発生しません。

自動実行スクリプトが CLI で別のイベントを発生させると、連鎖することがあります。繰り返し実行を防ぐため、自動実行中や終了直後は、新たな自動実行をしばらく保留します。

## スクリプトでできること

スクリプトで使用できる Tasty 関数は次のとおりです。

| 関数 | 動作 |
|---|---|
| `tasty.tree()` | ワークスペース・ペイン・タブ・サーフェスの構造のコピーを Lua テーブルとして返します。最上位はワークスペースの配列で、ウィンドウの階層は別途ありません |
| `tasty.run_cli(args)` | `tasty` コマンドを実行します。文字列 1 つ、または文字列のテーブルを渡してください |
| `tasty.log(msg)` · `tasty.warn(msg)` | ログに記録します |
| `tasty.on(event, cb)` | イベント発生時に呼び出される関数を登録します。イベントを受け取って後続の処理を行えますが、すでに発生したイベントの取り消しや変更はできません |

tasty を実際に操作する処理は、主に `tasty.run_cli` で行います。ワークスペースの作成も通知の送信も、[CLI](../agents/cli.md) でできることはすべてここでもできます。

```lua
-- ワークスペース数をログに記録して通知を送信
local tree = tasty.tree()
tasty.log("workspaces: " .. tostring(#tree))
tasty.run_cli({ "notify", "新しいワークスペース", "--title", "script" })
```

Lua 標準ライブラリのファイル入出力や外部コマンド実行は、そのまま使用できます。自分のコンピューターで作成したスクリプトを実行し、別のサンドボックスには隔離しません。

### `tasty.tree()` の戻り値の構造

`tasty.tree()` は、呼び出し時点で最後に作られたツリーのコピーを返します。返されたテーブルを変更しても、Tasty の状態は変わりません。`tasty.run_cli` は実行を要求するだけで完了を待たないため、直後に `tasty.tree()` を呼び出しても、その結果が反映されているとは限りません。

ワークスペースはウィンドウ単位で配列に追加されます。開いているウィンドウ（非表示や最小化されたウィンドウも含みます）のワークスペースが先に並びますが、ウィンドウ間の順序は固定されていません。macOS で Tasty の **最小化** <!-- en: Minimize --> によりバックグラウンドに送ったウィンドウのワークスペースは、送った順に続きます。1 回の操作でまとめて送ったウィンドウ間の順序は固定されていません。

| 階層 | フィールド |
|---|---|
| ワークスペース | `id`, `name`, `active`（そのウィンドウで選択されたワークスペース。バックグラウンドに送ったウィンドウも含みます）, `busy_count`（ワークスペース内の busy 状態のサーフェス数）, `panes` |
| ペイン | `id`, `focused`（そのワークスペースのフォーカスペイン）, `busy_count`, `tabs` |
| タブ | `id`, `name`, `active`（そのペインで選択されたタブ）, `busy`, `surface` |
| `tab.surface`（分割されたタブ） | `type = "SplitLayout"`, `focused_surface`（そのタブのフォーカスサーフェスの id）, `surfaces`（タブ内のサーフェス id の配列）, `layout` |
| `layout` ノード | `Leaf`: `type`, `id`, `kind`。`Split`: `type`, `direction`（`horizontal` ・ `vertical`）, `ratio`, `focus_second`, `first`, `second` |
| `tab.surface`（分割されていないタブ） | サーフェス 1 つです。すべてのサーフェスに `id` と `type` があり、ほかのフィールドは種類によって異なります。ターミナルは `type = "Terminal"` で、`cols` ・ `rows` はこのツリーでは常に 0 です |

### フォーカスサーフェスを探す

ウィンドウ 1 つのフォーカスサーフェスの id は、次の順序で探します。バックグラウンドに送ったウィンドウも含まれます。

1. `active` が真のワークスペースを探します。
2. その中で `focused` が真のペインを探します。
3. その中で `active` が真のタブを探します。
4. `tab.surface.type` が `"SplitLayout"` なら `tab.surface.focused_surface`、それ以外なら `tab.surface.id` を読み取ります。

```lua
local function focused_surface_id()
  for _, ws in ipairs(tasty.tree()) do
    if ws.active then
      for _, pane in ipairs(ws.panes) do
        if pane.focused then
          for _, tab in ipairs(pane.tabs) do
            if tab.active then
              local s = tab.surface
              return s.type == "SplitLayout" and s.focused_surface or s.id
            end
          end
        end
      end
    end
  end
end
```

### ツリーで区別できないこと

`active` と `focused` はウィンドウごとに決まり、バックグラウンドに送ったウィンドウも含まれます。ウィンドウが複数あれば、`active` が真のワークスペースも各ウィンドウに 1 つずつあります。ツリーにはウィンドウを示すフィールドがないため、OS のフォーカスがあるウィンドウや画面に表示されているウィンドウを区別できません。上の例のように最初の `active` ワークスペースを選ぶと、別のウィンドウのサーフェスが返ることがあります。Tasty を **最小化** でバックグラウンドに送った状態では、画面に表示されていないウィンドウのサーフェスが返ることがあります。

現在、サーフェスの実際の busy 状態と一致するのは、ワークスペースの `busy_count` だけです。タブの `busy` とペインの `busy_count` は、サーフェスの実際の状態を表しません。サーフェスオブジェクトに `busy` フィールドはありません。

## ファイルが変更された場合

登録時にファイルのハッシュを記録し、実行するたびに現在のファイルと比較します。エディターでスクリプトを修正すると、一覧に **変更あり** <!-- en: changed --> バッジが付きます。

- **ショートカットで実行** — 確認ダイアログが表示されます。承認すると新しい内容で実行し、ハッシュを更新します。更新したハッシュはすべてのウィンドウに適用されるため、別のウィンドウで実行しても再度確認されません。
- **自動実行** — 実行をブロックし、通知一覧に警告通知を記録します。人が見ていない間に変更されたスクリプトが実行されるのを防ぐためです。一覧でバッジを確認し、一度手動で実行して承認すると、再び実行されます。

`require` で読み込む別のファイルまでは検査しません。

## 実行の制約

- メモリの上限があり、超えるとその実行だけが中断されます。
- Lua 命令の実行中は時間制限を確認し、無限ループを中断します。ファイル入出力や外部コマンドで待機している間は、すぐに中断できない場合があります。アプリの画面は別に動作します。
- テキストソースのみ受け付けます。コンパイル済みのバイトコードは拒否します。
- デバッグライブラリと任意のコードをロードする系統の関数はブロックされています。

## 問題が発生した場合

- **ショートカットで実行したスクリプト** — 実行できなかった場合や失敗した場合は、ショートカットを押したウィンドウに失敗のトーストが表示されます。登録がなくなった場合、ファイルを読み取れなかった場合、スクリプトがエラーを起こした場合、時間制限を超えた場合、実行キューがいっぱいの場合が該当します。結果が届く前にそのウィンドウを閉じた場合、別のウィンドウには表示しません。
- **自動実行** — ファイルが変更されてブロックされた場合、読み取り・実行に失敗した場合、連鎖を防ぐためにスキップした場合は、通知一覧に警告通知が記録されます。ポップアップは表示されません。同じ内容の通知は 10 秒以内に 1 回だけ記録されます。

成功した実行には何も表示しません。詳しい原因はログレベルを上げて確認してください。

```sh
TASTY_LOG=tasty_lua=debug tasty
```
