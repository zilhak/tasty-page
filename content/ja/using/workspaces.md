# ワークスペース

Tasty のワークスペースは、プロジェクトやタスクで使うターミナルとレイアウトをまとめ、名前とカテゴリで区別してサイドバーで切り替えられます。

## 作成

| 方法 | 動作 |
|------|------|
| サイドバーの一番下にある **新しいワークスペース** <!-- en: New Workspace --> ボタン | ターミナルが 1 つのワークスペースを作成します |
| `Alt+N` （macOS `Cmd+N`） | 同じ動作です |
| **新しいワークスペース** ボタンを右クリック > **プリセットからワークスペースを作成...** <!-- en: Create workspace from preset... --> | 保存済みのレイアウトプリセットから作成します（[レイアウトの保存](panes-tabs-splits.md#レイアウトの保存--プリセット)） |
| サイドバーの空いている場所を右クリック > **リモートワークスペースを追加** <!-- en: Add remote workspace --> | 別のコンピューターの tasty をミラーリングします（[リモートで作業を続ける](../remote/attach.md)） |

新しいワークスペースのターミナルは、現在のターミナルの作業ディレクトリで起動します（**設定** > **ターミナル** <!-- en: Terminal --> > **作業ディレクトリを継承** <!-- en: Inherit working directory -->、デフォルトでオン）。

ターミナル以外のサーフェスで開始する場合や、作成時に名前を指定する場合は CLI を使ってください。

```sh
tasty new workspace --name build --cwd ~/proj
tasty new workspace --type explorer --path ~/proj
tasty new workspace --type markdown --file README.md
```

## 名前・サブタイトル

デフォルトの名前は `Workspace 1` のような連番です。サイドバーのカードを右クリックすると変更できます。

- **名前の変更** <!-- en: Rename --> — ショートカットは `F3` です。
- **サブタイトルの変更** <!-- en: Change Subtitle --> — カードの下にある小さな文字です。ショートカットは `F4` です。

```sh
tasty set workspace --id 3 --name api --subtitle "port 8080"
tasty list workspaces
```

## 切り替え

- サイドバーのカードをクリックしてください。
- `Alt+1` ～ `Alt+9` （macOS `Cmd+1` ～）。`Alt` を押している間は、カードの横に数字のキーキャップが表示され、どの番号かがわかります。
- `Alt+J` / `Alt+K` — 次 / 前のワークスペースに切り替えます。端まで行くと反対側に戻ります。
- 通知パネルの **移動** <!-- en: Jump --> ボタン — 通知を送ったサーフェスまたはワークスペースへ移動します。送信元が閉じている場合、ボタンは無効になります。

修飾キーと数字キーは、**設定** > **キーバインド** <!-- en: Keybindings --> の **ワークスペース切り替えの修飾キー** <!-- en: Workspace switch modifier --> 項目で変更してください。

ワークスペースごとに、フォーカスされたペインを個別に記憶します。別のワークスペースに移動して戻っても、カーソルがあった位置は維持されます。切り替えるとサイドバーの一覧が自動でスクロールし、アクティブなカードが表示されます。

## 順序を変更する

- カードをドラッグしてください。
- カードを右クリック > **上へ移動** <!-- en: Move Up --> / **下へ移動** <!-- en: Move Down --> を選択してください。
- `tasty move workspace --id 5 --to 0` — 移動するワークスペースを **ID で** 指定します。ウィンドウが複数あっても、その ID を持つウィンドウ内で移動します。ID は `tasty list workspaces` に表示されます。
- `tasty move workspace --from 2 --to 0` （0 から数えます）— 順番は **ウィンドウ内の位置** なので、ウィンドウが複数ある場合は現在表示しているウィンドウ内で移動します。

## カードに付く表示

| 表示 | 意味 |
|------|----|
| 名前の左側の点 | そのワークスペース内でプログラムが実行中です（`● 3` のように個数も表示します） |
| 名前の右側の数字バッジ | 確認が必要なサーフェスの数です。黄色は入力待ち、青色はタスクが終了したことを示します。そのサーフェスをクリックすると消えます |
| **リモート** <!-- en: REMOTE --> ピル | リモートの tasty をミラーリングしたワークスペースです |
| 名前の左側の点を囲む薄紫色の枠 | 別のユーザーがリモートで占有中です |

サイドバーを折りたたむと（**折りたたむ** <!-- en: Collapse -->、`Ctrl+B`）、カードが正方形のアイコンになり、表示も小さくなります。右上の点は個数を表示せず、最も緊急なもの 1 つだけを色で示します — 黄色は入力待ち、青色は終了したタスク、緑色は実行中です。**リモート** ピルは右下の水色のチップに変わります。別のユーザーがリモートで占有中の場合、薄紫色の枠は点ではなく **正方形のアイコン全体** を囲みます。

## 閉じる操作と復元

- カードを右クリック > **ワークスペースを閉じる** <!-- en: Close Workspace -->、または `Alt+Shift+W` を使ってください。
- リモートのミラーカードには **ワークスペースの接続を切る** <!-- en: Disconnect Workspace --> も表示されます。ミラーで **ワークスペースを閉じる** を選ぶとリモートコンピューターのワークスペースを閉じ、接続の切断ではリモートをそのままにして自分側のミラーだけを閉じます（[ミラーを閉じる操作と接続の切断](../remote/attach.md#ミラーを閉じる操作と接続の切断)）。
- `Ctrl+W` は **アクティブな項目を閉じる** <!-- en: Close active --> 操作です — タブが 1 つ残っている場合はペインを、ペインも 1 つの場合はワークスペースを閉じます。

リモートからアタッチして使用中のターミナルが含まれている場合は、閉じずに案内が表示されます。そのターミナル
で現在ほかの人が作業しており、閉じるとそのセッションが予告なく終了するためです。占有を解除
するには、占有表示の **強制切断** <!-- en: Force detach --> を押してから、もう一度閉じてください。
そのワークスペースに切り替えたくない場合は、サイドバーのカードを右クリックしてもかまいません — 占有中の場合にだけ
**強制切断** <!-- en: Force detach --> 項目が表示され、押すと確認ポップアップが 1 回表示されます。

ユーザーが閉じたワークスペース・ペイン・タブ・サーフェスは、`Ctrl+Shift+T` で最近の項目から復元してください。復元履歴は最大 10 件保持し、同じレイアウトスロットを正常に開き直した場合も履歴は維持されます。ターミナル履歴は内容の復元設定に従って復元されます。シェルは新しく起動し、保存済みのセッション再開コマンドがあれば実行します。CLI で閉じた項目は、この復元一覧には入りません。

閉じる項目のターミナル履歴は、64 MiB の保留中リクエスト用の容量から、ほかの保留中リクエストと閉じる履歴自体が占めるサイズを差し引いた範囲内で保持します。そのため、スクロールバックが 64 MiB より小さくても、残りの容量に収まらない場合は、そのターミナルをスクロールバックなしで復元一覧に残し、閉じる処理を進めます。この場合、通知パネルに警告が 1 件残り、リモートアタッチで開いたワークスペースで閉じた場合は、閉じる操作をしたウィンドウに警告の案内が 1 回表示されます。内容を省略したターミナルを復元すると、同じディレクトリで空のスクロールバックで開き、一緒に保持したほかのターミナルの履歴は内容の復元設定に従って復元されます。この警告は、実行中のレイアウトと内容の保存がすべて停止したという意味ではありません。

## カテゴリ（フォルダー）にまとめる

ワークスペースが増えたら、**設定** > **一般** <!-- en: General --> > **ワークスペースカテゴリ（フォルダー）** <!-- en: Workspace categories (folders) --> をオンにしてください。サイドバーが折りたためるセクションに変わります。

- デフォルトのセクション **ワークスペース** <!-- en: Workspaces --> は常に一番上にあり、名前の変更や削除はできません。
- セクションヘッダーをクリック — 折りたたみ / 展開を切り替えます。**すべてのカテゴリを折りたたむ/展開する** <!-- en: Collapse/expand all categories --> ショートカットはデフォルトでは未設定なので、自分で割り当ててください。
- ヘッダーを右クリック — **ワークスペースを追加** <!-- en: Add workspace --> · **プリセットからワークスペースを作成...** · **リモートワークスペースを追加** · **カテゴリ名を変更** <!-- en: Rename category --> · **カテゴリを削除** <!-- en: Delete category --> · **新しいカテゴリ** <!-- en: New category --> が表示されます。
- 空いている場所を右クリック — **新しいカテゴリ** · **リモートワークスペースを追加** が表示されます。
- ワークスペースのカードを右クリック — **カテゴリへ移動** <!-- en: Move to category --> が表示されます。別のセクションへドラッグすることもできます。
- カテゴリを削除しても中のワークスペースは削除されず、**ワークスペース** セクションに戻ります。

カテゴリをオンにするとサイドバー下部の **新しいワークスペース** ボタンが消え、ヘッダーメニューから作成します。`Alt+N` は、現在のワークスペースが属するカテゴリに作成します。

切り替えショートカットにもカテゴリ単位の操作が加わります。

| ショートカット | 動作 |
|--------|------|
| `Ctrl+Shift+1` ～ `Ctrl+Shift+0` | n 番目のカテゴリへ移動します。折りたたまれていれば展開し、そのカテゴリで最後に使ったワークスペースへ移動します。`Ctrl+Shift` を押している間はヘッダーに番号が表示されます |
| `Ctrl+Shift+J` / `Ctrl+Shift+K` | 次 / 前のカテゴリへ移動します |
| `Alt+1` ～ `Alt+9` | 現在のカテゴリ **内の** n 番目のワークスペースへ移動します |
| `Alt+J` / `Alt+K` | 現在のカテゴリ内で次 / 前へ移動します。境界を越えて次のカテゴリへ移動するには、**設定** > **一般** > **次/前のワークスペースへの移動時に他のカテゴリも含める** <!-- en: Next/prev workspace crosses categories --> をオンにしてください |

カテゴリを再びオフにすると、すべてのワークスペースが **ワークスペース** セクション 1 つにまとめられます。

```sh
tasty workspace-category list
tasty workspace-category create --name work
tasty new workspace --name api --category work
tasty set workspace --id 3 --category work
```

存在しないカテゴリを指定するとエラーになり、ワークスペースの作成や名前などの変更は行いません。

## 再起動後の復元

**起動時にレイアウトを復元** <!-- en: Restore layout on startup --> をオンにすると、保存されたワークスペース・ペイン・タブ・サーフェスのレイアウトを開き直します。**再起動時にサーフェスの内容を復元** <!-- en: Restore surface content on restart --> は、ターミナル履歴を再表示するかどうかを決めます。実行中だったプログラムと環境変数は、そのまま復元されません。エージェントセッションは、連携設定と保存済みの再開コマンドがある場合に再接続します。

現在のレイアウトは `~/.tasty/structure/journal.db` に保存されます。以前のバージョンの `layouts/01.json` のようなファイルは、初回の移行時だけ読み込みます。レイアウトが戻らない場合は、[トラブルシューティングの復元案内](../help/troubleshooting.md#設定やウィンドウの構成が初期化されたように見える場合)に従ってください。

再起動時に表示されるウィンドウは 1 つで、残りのスロットは新しいウィンドウ（`Alt+Shift+N`）を開くときに復元されます。

ウィンドウなしで動作する [ヘッドレスビルド](../getting-started/install.md#ヘッドレスビルド) の Tasty は、この設定にかかわらずレイアウトの保存も復元も行いません — ワークスペースはその実行中だけ存在します。設定がオンの場合は、起動時にその旨を警告 1 行で記録します。

Tasty がすでに実行中のときにもう一度起動しても、2 つ目の Tasty は起動しません。アプリメニュー・ランチャーから起動した場合は、開いていたウィンドウが前面に表示され、ターミナルで `tasty` を実行した場合は、新しいウィンドウが 1 つ開いて次の空きスロットを引き継ぎます（Windows では、前面にあるターミナルから実行すると、開いていたウィンドウが前面に表示される場合があります）。詳しい動作は [Tasty を再び起動した場合](../help/troubleshooting.md#tasty-を再び起動した場合)を参照してください。

よく使うレイアウトを別途保管するには、プリセットとして保存してください。[レイアウトの保存](panes-tabs-splits.md#レイアウトの保存--プリセット)で方法を確認できます。
