# 将后台任务移入标签页

Tasty 支持在不带标签页的隐藏 PTY 中运行任务，再将其移入标签页，同时保留同一进程和历史记录。移入标签页前也可以查看输出。

<!-- tasty-diagram: background-task -->
```
正在读取的日志：保持原样 | 正在运行的隐藏 PTY：移入新标签页
```

## 准备

打开 Tasty 窗口，在其中的终端运行以下命令。如果 `tasty` 命令无法连接，先查看 [CLI 准备](cli.md#准备)。

这里介绍的是运行中的 Tasty 内的**不带标签页的 PTY**。这与在服务器上使用无图形界面的无界面构建运行 Tasty 本身不同。

以下输入示例适用于 Bash、Zsh、Git Bash。数字 `2147483648` 和窗格 ID `1` 均为示例，务必替换为实际响应中的值。

## 1. 打开不带标签页的 Shell

```sh
tasty pty spawn
tasty pty list
```

记录创建响应中的 PTY ID。新 PTY 会出现在列表中，但屏幕上不会创建标签页。由于启动时未指定命令，Shell 会等待输入。

也可以同时指定起始文件夹和首先运行的命令。

```sh
tasty pty spawn --cwd ~/proj -- cargo test
```

`--cwd` 设置 PTY 的工作文件夹。`--` 后的内容会立即在 PTY 的 Shell 中执行。

## 2. 发送命令并读取输出

```sh
tasty pty write --id 2147483648 $'pwd\n'
tasty pty read --id 2147483648 --lines 20
```

`read` 默认跳过暗淡显示的文字（例如 Claude Code 的自动补全建议）。这是为了避免将尚未提交的建议误认为实际输出；如需一并读取，添加 `--show-dim`。

`write` 原样发送收到的字符。Bash 系列的 `$'...\n'` 包含实际换行符，因此会提交命令。这与普通双引号中的 `"...\n"` 不同。

如果在 PowerShell 中运行，按以下方式编写输入命令。

```powershell
tasty pty write --id 2147483648 "pwd`n"
```

检查输出中是否显示工作目录。如果尚无输出，使用 `read` 再次检查。可以用相同方式运行所需任务。

## 3. 检查运行状态

```sh
tasty pty state --id 2147483648
```

`state` 会立即返回当前是否已退出，不会阻塞到退出为止。如需等待，再次调用。旧名称 `pty wait` 仍可使用，行为相同。Shell 仍在运行时，`exited` 为 `false`。进程结束后，还可以查看退出码和是否成功。

Shell 内的一条命令结束，并不意味着 Shell 本身已退出。请区分 PTY 的退出状态与各条 Shell 命令的结果。

## 4. 在标签页中查看同一任务

```sh
tasty list panes
tasty pty attach-surface --pty 2147483648 --pane 1
```

使用从列表中选取的窗格 ID。**只有仍在运行的 PTY** 才能移入标签页。会创建一个保留进程和输出历史记录的新后台标签页，原 PTY ID 则从 `pty list` 中移除。

如果移入失败，进程不会终止，而是恢复为原 PTY ID。极少数情况下，如果无法恢复为原 ID，会收到需要恢复的错误（`-32068`）；该进程不会出现在 `pty list` 中，但会一直保留到 Tasty 退出。

当前查看的画面不会自动切换。需要查看时，手动选择新标签页。转换响应中包含新标签页和 Surface 的 ID，后续 CLI 操作使用这些 ID。不要再使用旧 PTY ID 调用 `pty read` 或 `pty kill`。

## 5. 清理任务

- 如果仍是隐藏 PTY，使用实际 ID 运行 `tasty pty kill --id 2147483648`。这会终止对应进程，并将其从隐藏 PTY 列表中移除。
- 如果已移入标签页，完成任务后关闭该标签页。此时不再通过隐藏 PTY 列表清理。

隐藏 PTY 的数量没有限制，即使列表中仍有已结束的 PTY，也可以创建新 PTY。如需控制同时运行的数量，使用[任务顺序管理](tasks.md)中的 semaphore。

即使长时间未检查，Tasty 也不会终止正在运行的 PTY。它会一直运行，直到手动 `kill`。如果希望在一段时间未检查后终止，创建时传入 `--idle-timeout <秒>`。如果在这段时间内没有调用 `read`、`write`、`state`，Tasty 会终止进程并留下警告通知。后台输出不会延长这段时间。

已结束的 PTY 会保留在列表中，以便查看退出码。从 Tasty 在列表清理过程中首次确认退出的时间与最后一次调用 `read`、`write`、`state` 的时间中较晚的一个开始，经过 5 分钟后会清理，并留下说明已清理的信息通知。Tasty 会定期检查已结束的 PTY，因此首次确认的时间最多可能比实际退出晚 1 分 30 秒。

## 出现问题时

- 如果找不到 PTY，使用 `tasty pty list` 检查。它可能已移入标签页或已被清理。如果是 Tasty 清理的 PTY，错误消息会说明是空闲超时到期，还是清理已结束的 PTY，通知中也会留下记录。
- 已退出的 PTY 无法移入标签页。查看输出和退出状态后再清理。
- 如果输入未执行，检查是否发送了实际换行符。

普通子终端和输出读取功能见 [CLI 指南](cli.md)，任务依赖关系和失败处理见[任务顺序管理](tasks.md)。
